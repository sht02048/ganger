# 0188 모바일 계획 문서를 지금 코드에 맞추기

## 목표

모바일 계획(스펙 [0002](../spec/0002-mobile.md), research [0014](../research/0014-mobile-client.md), ADR [0015](../adr/0015-device-token-pairing.md)·[0016](../adr/0016-mobile-push-via-expo.md), 티켓 0104~0112)은 2026-11-19에 썼다. 그 뒤 0113~0183 머지와 v0.4.0 출시로 도메인과 화면이 바뀌었다. 계획을 지금 코드에 맞추고 2026-11-23 운영자 결정을 넣는다. 문서만 바꾼다.

## 운영자 결정 (2026-11-23)

스펙 0002 11절의 M22~M30이다.

1. M22: 모바일에서 Human Check에 답한다. Question과 같은 시트 방식이고 알림 버튼은 "확인하기"다.
2. M23: Human Check 알림은 지금 동작대로 소리가 있고 데스크톱은 10분 뒤 다시 알린다.
3. M24: 모바일은 재개만 한다. 멈추기는 나중이다.
4. M25: v1 쓰기는 거절을 포함해 모두 `requestId`가 필수다.
5. M26: 변경 기록 SSE를 v1 아래 기기 토큰 인증으로 연다. 앱이 앞에 있을 때만 붙고 실패하면 폴링한다.
6. M27: v1 응답에 서버 버전과 계약 버전을 싣고 앱에 최소 서버 버전을 둔다. `/api/build`는 웹 전용이다.
7. M28: 기다리지 않고 시작, 에이전트에게 보내기는 모바일에서 뺀다.
8. M29: 알림 사건 종류는 지금 8종 그대로다. 멈춘 기다림, 보고 없이 멈춘 Paused, PR CI 실패는 모바일 Dashboard에서 보이기만 한다.
9. M30: 모바일 "처리할 일만" 기준은 티켓 단위 To do다.

## 범위

- 스펙 0002의 사실을 고치고 M22~M30을 더한다. 열린 질문 4는 결정 완료로 닫고 3·8·9·13은 바뀐 전제로 다시 쓴다. 나머지 열린 질문은 그대로 둔다.
- ADR 0015·0016은 결정이 바뀐 줄만 고치고 갱신 메모를 단다. research 0014는 본문을 보존하고 갱신 메모만 더한다.
- 티켓 0104~0112의 낡은 내용을 고치고 풀린 선행 0103을 지운다.
- GLOSSARY의 옛 Dashboard 제목과 ADR 0010의 Human Check 줄을 고친다. ADR 0010의 Runs·Dashboard 문구는 다른 티켓이 고쳐 건드리지 않는다.

## 범위 밖

- 코드 변경, 새 결정, 티켓 새로 쪼개기.

## 완료 조건

- 바꾼 문서의 상대 링크가 깨지지 않는다.
- 커밋 훅(format)을 통과한다.
- 독립 리뷰가 문서와 코드, 결정 반영을 확인한다.
