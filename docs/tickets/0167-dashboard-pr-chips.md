# 0167 Dashboard 카드에 PR 칩

## 목표

PR의 CI 실패·충돌·뒤처짐(0150)은 Runs 행과 Run 상세에만 보인다(스펙 0006 C7). 그래서 Dashboard 카드에서는 같은 런의 PR이 CI 실패인지 알 수 없다. 운영자 결정(2026-11-21)으로 Dashboard 카드의 칩 줄에 PR 칩을 보인다. 스펙 0006 C7의 "Runs 행과 Run 상세 PR 구역에만"을 넓힌다.

## 결정 (시안 CiCases 보드의 규칙)

- PR 칩은 런의 PR이 Open일 때만 보인다. Merged·Closed면 보이지 않는다. PR을 못 읽었으면(pr_read_error) 칩 대신 바닥 줄 PR 자리에 "PR 못 읽음"을 흐리게 쓴다. 지난 신호를 남겨 보이지 않는다.
- 종류와 순서(급한 순서): CI 실패(문제색, ✕ 아이콘) → 충돌(문제색, ⇄ 아이콘) → base N커밋 뒤(경고색, ↓ 아이콘). CI 도는 중·통과·충돌 없음·최신은 칩을 만들지 않는다.
- 칩 줄 안에서는 선행 티켓 칩(점 + 번호)이 먼저, PR 칩이 뒤에 온다. PR 칩은 두 개까지 보이고 나머지는 `+N` 칩 하나로 묶는다. 선행 티켓 칩의 지금 개수 규칙은 그대로다.
- 칩은 상태 묶음에서 내용(질문 문장·Failed 이유 등) 아래, 바닥 줄 위에 둔다. To do 꼬리표는 오른쪽 위 그대로이고, 런 결과와 To do 종류는 바꾸지 않는다(스펙 0005 R1).
- 모든 칸(Queued·Running·Done)의 카드에 같은 규칙을 쓴다. Done 칸 "처리할 일 없이 끝났어요" 카드도 같다.
- 칩 글은 카드 버튼의 설명(`aria-describedby`)에 들어가 화면 읽기에서도 들린다.
- 스펙 0006 C7과 `packages/ui/DESIGN.md`의 `KanbanCard` 설명(칩 줄)을 고친다.

## 완료 조건

- 시험: PR 없음, Open+CI 실패, Open+충돌+뒤처짐+CI 실패(두 개 + `+1`), Merged(칩 없음), 못 읽음(바닥 줄 문장), 선행 칩과 PR 칩이 함께(순서), Question 카드의 질문 문장 아래 위치, 접근 이름에 칩 글.
- 스크린숏: Dashboard에 시안 1·3·4·6번 같은 카드가 섞인 상태. 가상 데이터. 1440 폭 다크.
- DB 변경 없음. two-way.
