# 0173 Runs 목록을 러너 기준으로 단순하게

## 배경

운영자(2026-11-22): 지금 Runs는 복잡하고 상태가 많아 한눈에 파악하기 어렵다. 기준을 러너로 바꾼다.

## 운영자 결정(2026-11-22)

- 맨 위에 상황 문장 하나를 둔다. 0인 부분은 빼고, 끊긴 런이 있으면 맨 앞에 말한다.
- "지금" 구역은 러너마다 카드 하나다. 자리 8개까지는 칸, 넘으면 막대와 숫자이고, 꺼진 러너는 "꺼져 있어요"다. 카드 안에는 끝나지 않은 런을 4개까지, 답을 기다리는 런부터 보인다.
- 카드 순서는 답·끊김, 도는 런, 빈 러너, 꺼진 러너이고 같은 단계는 이름 순이다. 꺼진 러너에 끊긴 런이 있으면 카드를 흐리게 하지 않는다.
- 러너가 정해지지 않은 Queued는 맨 오른쪽 "자리를 기다려요" 카드에 오래 기다린 순서로 5개까지 보인다. 좁은 화면에서는 이 카드가 맨 위다.
- "끝난 런" 표는 확인 필요가 있으면 그것만 먼저 보이고, "확인 필요 N / 모두 N"으로 바꾼다. 기간은 오늘·7일·30일이고 **기본은 7일**이다. 러너 메뉴를 두고, 내리면 이어서 불러온다.
- 목록과 문장의 상태는 한국어 한 마디로 쓰고, 영어 상태 이름은 패널과 런 상세의 알약에만 남긴다.
- 묶음 탭과 상태 칩 8개를 없앤다. 러너·프로젝트·에이전트·기간 조건은 URL로 받아 지울 수 있는 칩으로 보인다.
- 패널은 처리할 일 상자, PR 구역, 짧은 런 정보, "런 상세 열기"다. 처리할 일 문장은 런 상세와 같은 공용 함수(`runNextStep`, 0174)를 쓴다.
- Runners 상세는 러너별 런 목록을 빼고 "Runs에서 보기" 링크만 둔다.

## 결정에 없어 구현에서 정한 것

- 러너 자리 수는 다른 Workspace의 런까지 센다. 러너의 실제 자리이기 때문이다. 카드의 런 목록은 고른 Workspace의 런만 보인다.
- 러너가 미리 정해진 Queued 런도 "자리를 기다려요" 카드에 둔다. 러너 카드에는 자리를 차지한 런만 둔다.
- 상황 문장은 Paused 런을 세지 않는다. Paused 런만 있으면 "지금 도는 런이 없어요"이고 카드에는 "멈춰 있어요"로 보인다.
- 러너 메뉴와 URL `runner` 조건은 같은 값이라 "지금" 카드도 그 러너로 좁혀진다.
- 러너·프로젝트·에이전트 조건이 걸리면 끝난 런 표는 처음에 모두를 보인다. Stats·Tickets·Runners에서 그 조건의 런을 보러 온 것이기 때문이다. 토글은 그대로 쓸 수 있다.
- 프로젝트·에이전트 조건이 걸리면 맞는 런이 있는 러너 카드만 보인다.
- 지워진 러너의 끝나지 않은 런은 꺼진 카드로 보여 잃지 않는다.
- Stats 링크의 `days=14`와 `f=failed`는 `stats.tsx`를 고치지 않고 지울 수 있는 칩으로 받는다. 그 밖의 옛 `f` 값은 무시한다.
- 새 런이나 이어서 맡긴 런이 있는 옛 런은 확인 필요에 넣지 않는다. 런 상세의 처리할 일과 같은 기준이다.
- 고른 런이 목록 밖(기간 밖 등)이어도 `sel`로 따로 읽어 패널을 연다. Tickets의 런 링크가 이 경로를 쓴다.
- MCP `list_runs`는 그대로 `loadRunsPage`를 쓴다. 화면 개편이 MCP 결과를 바꾸지 않는다.

## 완료 조건

- web 시험: 두 구역, 꺼진 러너의 끊긴 런, 좁은 화면 순서, 패널 열기와 `sel` 유지, Runners 링크.
- e2e: 기존 Runs 시험을 새 구조에 맞추고, 지운 시험이 지키던 동작은 PR 본문의 대응표로 남긴다.
- 스크린숏: 넓은 화면, 많을 때(러너 6대 이상), 좁은 화면, 패널.
