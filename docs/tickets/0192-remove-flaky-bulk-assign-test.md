# 0192 흔들리는 상위 이슈 한 번에 할당 시험 지우기

## 목표

`e2e/src/tickets.test.ts`의 「Tickets 상위 이슈 보기(브라우저, 0171) > 상위 이슈에서 하위 2개를 한 번에 할당하면 두 런이 Queued가 되고 포커스가 패널 제목으로 간다(0172)」가 PR과 상관없이 CI에서 실패해 `check`를 막는다. 운영자 결정(2026-11-20)대로 고치지 않고 지우고, 잃은 확인 범위를 여기에 남긴다.

## 실패 근거

- PR #247(0110, Tickets를 건드리지 않음)의 CI run 45097661795, 잡 `browser (1)`에서 `expect.poll() function didn't resolve in time`으로 실패했다.
- 실패 위치는 시험의 마지막 단언인 「할당 뒤 상위 이슈 줄의 버튼이 사라진다」 poll이다. 그 앞의 알림, 대화상자 닫힘, 포커스, 두 런의 Queued 단언은 통과했다.
- 같은 시험은 로컬에서 단독으로 3번 돌려 3번 통과했다.
- 0181 때는 `e2e/src/navigation-back.test.ts`에서 Tickets 줄을 눌러 고르는 단계가 CI에서 한 번 흔들렸다. 다른 파일의 시험이지만 Tickets 목록을 쓰는 점은 같다.

## 잃은 확인 범위

지운 시험은 다른 티켓을 고른 상태에서 상위 이슈 줄의 버튼으로 하위 2개를 할당하고, 알림, 대화상자 닫힘, 패널 제목 포커스, 두 런의 Queued, 버튼 사라짐을 실제 브라우저에서 이어서 봤다.

### 이미 지키는 부분

- 여러 티켓을 한 요청으로 할당하고 티켓별 결과를 돌려주는 일: `apps/web/src/tickets/bulk-assign.test.tsx`의 「한 번에 할당(0172)」.
- 할당한 런이 Mapping 값으로 Queued가 되는 일: 같은 파일의 「단일 할당과 같은 Mapping 값으로 Queued 런을 만든다」. 티켓 하나로 확인한다.
- 처음 선택에서 할당 전 하위 티켓을 체크하는 일: 같은 파일의 「하위 티켓 처음 선택(0172)」.
- 모두 성공하면 대화상자가 닫히는 일: `apps/web/src/tickets/bulk-assign-dialog.test.tsx`의 「보내는 동안에는 닫기를 눌러도 닫히지 않는다」. 티켓 하나로 확인한다.
- 할당할 수 있는 하위가 없으면 버튼을 그리지 않는 일: `apps/web/src/tickets/tickets-screen.test.tsx`의 「할당할 수 있는 하위가 없으면 버튼을 두지 않고, 모든 티켓 보기의 줄에도 두지 않는다」.
- 브라우저에서 상위 이슈 줄 버튼 → 대화상자 → 할당 → 닫힘 → Queued로 이어지는 흐름: `e2e/src/tickets.test.ts`의 「선행 티켓이 취소된 하위 티켓은 체크되지 않은 채 남아 할당되지 않는다(0176)」. 하위 하나만 할당한다.

### 아무도 지키지 않는 부분

- 할당에 성공해 대화상자가 닫힌 뒤 포커스가 상위 이슈 패널 제목으로 가는 일(`tickets-screen.tsx`의 `bulkFinalFocus`). 단위 시험은 할당 없이 닫을 때 포커스가 돌아가는 경우만 본다.
- 다른 티켓을 고른 상태에서 할당하면 패널이 그 상위 이슈로 바뀌는 일.
- 모두 성공했을 때 「N개 할당했어요.」 알림이 뜨는 일.
- 브라우저에서 하위 2개 이상을 한 번에 할당해 런이 모두 Queued가 되는 일.
- 할당 뒤 다시 읽은 목록에서 상위 이슈 줄의 버튼이 사라지는 일.

## 남은 의문

할당 뒤 상위 이슈 줄의 버튼이 제한 시간 안에 사라지지 않았다. CI 부하로 목록 다시 읽기가 늦었는지, 할당 뒤 목록을 다시 읽는 흐름의 제품 쪽 경쟁 상태인지는 재현하지 않아 확인하지 못했다.
