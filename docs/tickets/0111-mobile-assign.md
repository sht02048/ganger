# 0111 모바일 8: 앱에서 다시 맡기기·이어서 맡기기

## 목표

앱의 Failed 카드에서 이전 런과 같은 저장소·러너·에이전트로 다시 맡긴다. 워크트리가 남았으면 이어서 맡기기도 고를 수 있다. 둘 다 확인 시트를 거친다(스펙 [0002](../spec/0002-mobile.md) M3·M38).

## 범위

- 다시 맡기기: v1 쓰기로 `assignTicket`을 열고 이전 런의 저장소(`runnerProject`), 러너(`runnerId`), 에이전트(`agent`)를 그대로 보낸다(ADR 0018, 티켓 0155).
- 이어서 맡기기: v1 쓰기로 `continueRunFrom`을 연다. 워크트리가 남은 Failed 런에서 고를 수 있고, 서버가 허용하지 않으면(`continueRunBlock`) 두지 않는다. 운영자의 말이 필수이므로 확인 시트에 입력칸을 둔다(티켓 0149).
- v1 쓰기는 모두 `requestId`가 필수다(M25). `assignTicket`에는 아직 이 보호가 없다. 할당은 요청 때 런이 없어 `run_action_requests`(`run_id` 필수)를 그대로 쓸 수 없으므로, 할당용 키와 저장할 곳을 이 티켓에서 만든다.
- 지금 서버 규칙: 끝나지 않은 런이 있는 티켓은 할당할 수 없다(`active-run`). Disconnected 런은 끝나지 않은 런이라 다시 맡길 수 없다.

## 범위 밖

- 새 티켓 할당, 여러 티켓 할당(`assignTickets`), Queued 런 옮기기(M38).
- 기다리지 않고 시작(M28).

## 시작할 때 운영자와 정할 것

- M50(운영자 결정, 2026-11-23): 이전 런에 러너가 없거나(시작하지 못하고 끝난 런) 그 러너·저장소·Mapping이 사라져 같은 값으로 맡길 수 없으면, 앱은 다시 맡기기를 끄고 웹이나 데스크톱에서 맡기라고 안내한다. 앱에 러너·저장소 고르기는 넣지 않는다. 맡길 수 있는지는 서버가 판단해 v1 응답에 싣는다.

## 완료 조건

- Failed 카드에서 확인 시트를 거쳐 이전 런과 같은 저장소·러너·에이전트로 새 런이 생기는 시험이 있다.
- 워크트리가 남은 Failed 런에서만 이어서 맡기기를 고를 수 있고, 말 없이 보낼 수 없는 시험이 있다.
- 같은 `requestId`의 다시 맡기기가 런을 하나만 만드는 시험이 있다.
- 이어 만든 런이 없어졌거나 시작하지 못하고 끝났으면 같은 `requestId`의 이어서 맡기기를 다시 처리하는 시험이 있다.
- v1에 새 티켓 할당과 `assignTickets`가 열리지 않는 시험이 있다.
