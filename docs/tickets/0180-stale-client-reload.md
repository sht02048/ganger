# 0180 서버 버전이 바뀐 뒤 옛 화면 코드 다시 불러오기

운영자가 앱과 원격 서버를 0.4.0으로 올린 뒤 창으로 돌아오니 화면이 "화면을 열지 못했어요"를 보였고, "다시 읽기"도 실패했다. 앱을 다시 열면 풀렸다.

## 재현 (2026-11-22)

v0.3.0 서버에서 모든 화면을 연 창을 그대로 두고 서버만 0.4.0으로 바꿨다. Runs가 오류 화면을 보였고 "다시 읽기"도 실패했으며, 전체 새로고침만 풀었다. 이때 HTTP 오류는 없었다. 옛 코드가 새 서버의 응답을 읽지 못한 것이라 상태 코드로는 알아낼 수 없다. 아직 받지 않은 화면 코드는 404가 나고 라우터가 스스로 페이지를 다시 불러온다.

## 운영자 결정 (2026-11-22)

1. 화면 코드가 서버 빌드와 다른지 서버 함수·질의 실패 때와 창이 다시 보일 때 확인한다. 주기적 폴링은 하지 않는다.
2. 다르면 오류 화면의 "다시 읽기"가 페이지 전체를 다시 불러온다. 오류가 없는 화면에서는 자동으로 다시 불러오지 않고 알림과 "다시 불러오기" 버튼을 보인다.
3. 데스크톱 앱 보기 메뉴에 다시 불러오기(⌘R)를 둔다. 앱이 직접 켠 서버를 새 버전으로 바꾼 뒤에는 창을 스스로 다시 불러온다.
4. 빌드 식별자를 쓰면 같은 버전 개발 빌드끼리의 차이도 함께 잡는다.

## 결정

- 기준은 `vite build` 한 번마다 만드는 빌드 식별자다. 화면 코드와 서버 코드에 같은 값이 들어가, 버전이 같은 빌드끼리의 차이도 잡는다. 개발 서버는 늘 `dev`다. `vite build`가 설정 파일을 두 번 평가해 값을 환경 변수로 넘겨 맞추고, `smoke:web`이 화면 코드와 서버의 값이 같은지 확인한다.
- 서버는 `GET /api/build`로 알린다. `/api/identity`는 데스크톱 앱과의 계약이라 넓히지 않는다.
- Electron의 기본 보기 메뉴에 영어 Reload(⌘R)가 이미 있었다. 메뉴를 명시적으로 만들어 항목은 그대로 두고 이름만 한국어로 바꾼다.

## 완료 조건

- 단위 시험: 빌드 비교, 다시 읽기가 빌드가 다를 때 전체 다시 불러오기를 부르고 같을 때 기존 동작을 하는지, 알림 표시 조건, 데스크톱 메뉴, 서버 교체 뒤 다시 불러오기.
- 브라우저 시험: 서버가 보고하는 빌드가 바뀐 뒤 오류가 나면 다시 읽기가 새 페이지를 불러온다. CI와 비슷한 부하에서 5번 통과한다.
- 스크린숏: 서버 새 버전 알림.
- `docs/guide/desktop.md` Updates 절에 원격 서버를 올린 뒤 창의 동작을 적는다.
