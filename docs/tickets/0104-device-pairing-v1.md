# 0104 모바일 1: 기기 연결과 첫 v1 API

## 목표

다른 기기가 QR로 이 서버에 연결해 기기 토큰을 받고, 그 토큰으로 `/api/v1`에서 Dashboard를 읽는다. 기기 목록에서 지우면 그 토큰은 바로 거절된다. 모바일 앱 없이도 시험할 수 있는 서버 쪽 첫 경로다(스펙 [0002](../spec/0002-mobile.md) 10절 2번, ADR [0015](../adr/0015-device-token-pairing.md)).

## 범위

- 기기 표를 더하는 DB 마이그레이션(이름, 토큰 해시, 만든 때, 마지막 접속, Expo 푸시 주소, 알림 켜기, 종류별 켜기). 토큰은 만료하지 않고 지우기로 끊는다(M35). 되돌리는 방법을 PR에 적는다.
- 기기 연결 화면(웹 Settings, 데스크톱도 그 화면, M35): QR(다른 기기에서 열 주소 + 10분 동안 한 번만 쓰는 연결 코드. 0097의 러너 등록 토큰과 같은 수명과 길이)과 기기 목록(이름, 연결한 때, 마지막 접속, 지우기). 다른 기기에서 열 주소가 비었거나 https가 아니면 QR을 띄우지 않고 Settings의 주소 칸으로 안내한다.
- 연결 코드를 기기 토큰으로 바꾸는 경로. 연결 코드는 해시만 메모리에 두고(티켓 0097과 같은 방식), 토큰은 해시만 DB에 둔다.
- `/api/v1`의 토큰 확인(`Authorization: Bearer`). 기기가 스스로 연결을 끊는 경로. 데스크톱 앱이 쓰는 알림 사건 경로(`/api/notification-events`, 티켓 0103)는 0108 전까지 토큰을 요구하지 않는다.
- `packages/api`를 만들고 첫 읽기 계약(Dashboard 세 칸, 처리할 일, 요약 문장에 필요한 값)을 zod 스키마로 둔다. 계약은 지금 도메인을 담는다: 결과 Succeeded·Failed·Canceled와 PR 정보, Waiting for Input의 Human Check, Paused와 멈춘 이유, Queued 이유 9종과 선행 티켓, PR 칩, 취소 중.
- v1 응답에 서버 버전과 계약 버전을 싣는다(M27). `/api/build`는 웹 전용으로 둔다.
- GLOSSARY에 기기 토큰, 기기 연결, 연결 코드를 더한다. "페어링 코드"는 쓰지 않는다(Runner Enrollment의 _Avoid_).
- Expo 푸시 주소는 어느 화면과 API 응답에도 싣지 않는다(ADR 0016).

## 운영자 결정

- 기기 표의 종류별 켜기는 데스크톱 알림 설정과 같은 5묶음(Question, Permission, Human Check, Failed·Disconnected, Runner Issue)으로 둔다. 알림 사건 8종 각각이 아니다(스펙 0002 M47).

## 범위 밖

- 모바일 앱(0105, 0106), 쓰기 API(0107), 알림 사건 경로 이동과 데스크톱 인증(0108), 웹 화면 인증(M36, 모바일 범위 밖).

## 완료 조건

- 연결 코드로 토큰을 받고, 그 토큰으로 v1 Dashboard를 읽는 시험이 있다.
- 한 번 쓴 연결 코드, 만료된 연결 코드, 지운 기기의 토큰, 토큰 없는 요청이 거절되는 시험이 있다.
- 토큰 원문이 DB에 저장되지 않고 연결 코드 교환 응답 밖의 어떤 응답에도 실리지 않는 시험이 있다.
- 기기 목록 화면과 v1 응답 어디에도 Expo 푸시 주소가 실리지 않는 시험이 있다.
- v1 응답에 서버 버전과 계약 버전이 실리는 시험이 있다.
