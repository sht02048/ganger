# 0199 Dashboard 런 패널을 「런」·「PR」 탭으로 나누기

Dashboard에서 런 카드를 눌러 여는 오른쪽 패널은 상태·제목 아래 답하기·Human Check·거절 블록과 속성 정의 목록(에이전트 결과, PR 상태 글자, 티켓, 러너, 에이전트), Run 상세 링크를 한 줄로 쌓았다. PR이 어떤 상태인지 패널에서 바로 알 수 없었다(운영자 요청 2026-11-23).

## 운영자 결정 (2026-11-23)

1. 탭 위(고정)는 상태 알약, 경과 시간, 닫기, 티켓 키+제목이다. 그 아래 `Tabs`(노란 밑줄) 두 개: 「런」, 「PR」.
2. 「PR」 탭 이름: PR이 있으면 "PR #571"과 점 하나(접근 이름 있음). PR이 없으면 "PR"과 흐린 "없음". Queued 런은 「PR」 탭을 숨긴다. 점 색은 DESIGN.md 상태 색 규칙을 따른다.
3. 「런」 탭: 요약 칸 셋(러너, 에이전트, 일한 시간), 그 아래 "이름 | 값" 줄 목록(지금, 에이전트 결과, 티켓 링크, 기록 — Run 상세 보기). "확인하기" 버튼과 요청 문구 상자는 두지 않는다. answer 모드(카드의 "답하기"·"확인하기")에서는 「런」 탭 맨 위에 폼을 보이고, summary 모드(카드 본문)에서는 보이지 않는다. 0193의 보내면 닫기는 그대로다.
4. 「PR」 탭: CI, 충돌, base, PR(번호 ↗ 새 탭, 아래 브랜치) 줄 목록. 머지된 PR은 상태와 머지 시각, 닫힌 PR은 "닫힘". 판정 문장과 요약 줄은 쓰지 않는다. 없는 값은 "알 수 없어요".
5. PR이 없으면 "아직 PR이 없어요" + 한 줄 설명, 끝난 런이면 "PR을 만들지 않고 끝났어요".
6. 처음 열리는 탭: 할 일(Question·Human Check·Permission·Paused)이 있거나 answer 모드면 「런」, 끝난 런의 PR에 CI 실패·충돌이 있으면 「PR」, 그 밖에는 「런」. 고른 탭은 패널을 닫을 때까지 유지한다.
7. 「PR」 탭의 머지 버튼(0201)과 커밋 구역(0200) 자리는 비워 두고 구조만 나눈다.

## 구현에서 정한 것

- 점 색: CI 실패·충돌은 `problem`(빨강), 문제 없음(CI 통과·없음, 충돌 없음, base 최신)은 `progress`(초록), CI 도는 중·뒤처짐만 있으면 `idle`(회색), 머지됨 `merged`(파랑), 닫힘 `idle`, 판단할 값이 없으면 점 없음. 노랑은 사람이 직접 할 일과 강조에만 쓰고(DESIGN.md 5번, `PrChip`의 `behind`도 무채색) 상태 점에 빌리지 않는다.
- Permission은 카드에 따로 여는 버튼이 없어 summary 모드에서도 거절 폼을 보인다. 숨기면 거절할 길이 없어진다.
- PR 제목과 base 브랜치 이름은 저장하지 않아(새 열이 필요하다) 줄 이름은 "base", PR 줄은 번호와 head 브랜치만 보인다. 끝날 때 이미 머지된 PR은 머지 시각을 모른다.
- 멈추기·재개 버튼과 Failed 런의 "Tickets에서 다시 맡기기"는 「런」 탭 줄 목록 아래에 그대로 둔다.
- `packages/ui`: `Tab`의 `note`·`dot`, `TabPanel keepMounted`(탭을 오가도 쓰던 답이 남는다), `SignalRow`의 아이콘 없는 줄, 새 `FactCells`·`FactCell`.
