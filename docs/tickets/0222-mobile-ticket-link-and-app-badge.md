## 결정

1. **낱말은 "Linear에서 열기"다.** 운영자 확정 시안(2026-11-25)이 카드 메뉴·런 상세 모두 이 낱말을 쓰고, GLOSSARY의 Tracker는 "1단계에서는 Linear만 지원한다"고 적으며, 모바일의 기존 낱말과 웹 Tickets 목록(`tickets.json`의 `openInLinear`)도 같다. 앱으로 여는 동작도 Linear 앱을 기준으로 한다. 웹 Dashboard 런 패널과 Run 상세는 "트래커에서 열기"를 써서 웹 안에서 두 낱말이 섞여 있다. 웹 통일은 이 티켓 범위 밖이라 후속으로 남긴다.
2. **앱으로 열기는 유니버설 링크로 한다.** `linear.app/.well-known/apple-app-site-association`은 Linear iOS 앱(`com.linear.ios`)에 `*/issue/*` 경로를, `github.com/.well-known/apple-app-site-association`은 GitHub iOS 앱에 저장소 경로 전체(`*`, 제외 목록에 `pull`은 없다)를 등록해 `/{owner}/{repo}/pull/{번호}`가 들어간다. React Native `Linking.openURL`은 iOS의 `open(_:options:)`을 빈 옵션으로 불러, 그 주소를 맡은 앱이 깔려 있으면 앱이, 없으면 Safari가 연다. 그래서 트래커·코드 호스트가 준 웹 주소를 그대로 열고 주소를 바꾸지 않는다. `linear://` 스킴은 Linear 문서에 데스크톱 앱용으로만 적혀 있어 쓰지 않았고, 스킴을 쓰지 않으니 `LSApplicationQueriesSchemes`와 `canOpenURL`도 필요 없다(Expo Go에서도 같다). 한계: 사용자가 그 도메인 링크를 Safari로 열기로 고른 적이 있으면 iOS가 그 선택을 기억해 브라우저로 연다. React Native `Linking`은 `universalLinksOnly` 옵션을 내주지 않는다. 다른 트래커 어댑터도 웹 주소를 그대로 연다. 웹 주소 검사(`isWebLink`)는 그대로 둔다.
3. **"…" 메뉴 항목.** 위 묶음은 바깥 링크(Linear에서 열기, PR이 웹 주소이면 "PR #번호 열기"), 구분선 아래 묶음은 런 동작(끝나지 않았고 취소 중이 아닌 런의 "런 취소")이다. 이어서 맡기기·다시 맡기기는 Failed 카드의 "다시 맡기기" 시트에 이미 있어 메뉴에 겹쳐 두지 않았다. 런 취소는 팝오버를 닫고 지금의 취소 확인 시트를 연다. Done 칸의 끝난 런 줄(Succeeded·Canceled)에도 같은 메뉴를 둔다. 끝난 런에서 티켓을 열 길이 그 줄뿐이기 때문이다.
4. **팝오버 위치와 닫기.** 버튼 아래 4에 오른쪽을 맞추고, 화면 가장자리 8 안으로 당기며, 아래 자리가 모자라면 버튼 위로 연다. 바깥(접근 이름 "메뉴 닫기")을 누르거나 항목을 고르면 닫힌다. VoiceOver에서는 메뉴가 모달이라 항목과 "메뉴 닫기"에만 닿고, 두 손가락 문지르기(escape)로도 닫힌다. iOS는 Modal이 닫히는 도중에 새 Modal을 띄우지 못할 수 있어, iOS에서는 팝오버가 다 닫힌 뒤(`onDismiss`) 항목 동작을 부른다.
5. **앱 아이콘 배지는 서버가 푸시에 싣고, 앱이 열릴 때도 맞춘다.** 앱이 꺼져 있을 때 알림 푸시를 받아도 앱 코드는 돌지 않고, 조용한 푸시는 iOS가 미루거나 버릴 수 있다. 수를 아는 쪽은 서버라, worker가 알림 푸시마다 웹 레일 Dashboard 배지와 같은 함수(`loadShell(db).todo.all`, v1 Dashboard 요약의 처리할 일 합과 같은 값)로 `badge`를 싣는다. 조용한 지우기 푸시는 APNs 규칙대로 `content-available`만 담고, 같은 기기에 배지만 담은 푸시를 하나 더 보낸다. 푸시 데이터 형식(`PushData`)은 바꾸지 않아 이전 앱도 그대로 받는다. 보낼 푸시가 없는 틱에는 수를 세지 않는다.
6. **앱 쪽.** 앱이 열려 있으면 전체 Workspace Dashboard를 읽을 때마다 그 요약의 처리할 일 합으로 배지를 맞추고, 앞에 떠 있을 때 받은 푸시의 `badge`는 쓰지 않는다(`shouldSetBadge: false`). 알림을 끈 기기는 0, 데모 모드와 연결 화면(연결 끊기·토큰 거절 뒤)도 0으로 지운다. 알림 설정이나 전체 Dashboard를 아직 모르면 배지를 건드리지 않는다. 배지 권한은 알림 권한 요청(기본 `allowBadge`)을 따르고, 사용자가 iOS 설정에서 배지를 끄면 iOS가 보이지 않는다. 한계: 이 기기로 푸시하지 않은 사건(끈 종류 등)이 해결되면 다음 푸시나 앱을 열 때 맞는다.
7. DB와 v1 API 계약은 바꾸지 않았다.
