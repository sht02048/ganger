# 0172 하위 티켓 한 번에 할당

## 배경

0171이 Tickets를 상위 이슈로 묶었지만 하위 티켓은 아직 하나씩 할당한다. 운영자가 2026-11-22에 상위 이슈에서 하위 티켓을 한 번에 맡기는 흐름을 정했다.

## 할 일

### 자리

- 묶기 보기의 상위 이슈 줄 할 일 칸에 테두리만 있는 작은 버튼 "하위 N개 할당"을 둔다. 상위 이슈 패널 머리에는 같은 동작의 회색 보조 버튼을 둔다. 노란 주 버튼과 별도 줄·띠는 쓰지 않는다.
- N은 거르기·찾기와 상관없이 그 상위 이슈의 할당할 수 있는 하위 티켓 전체 개수다. N이 0이면 버튼이 없다. 하위가 있는 상위 이슈 자신은 할당 대상이 아니다.

### 확인 대화상자

- 제목은 "하위 티켓 할당하기"이고, 설명에 상위 이슈 키·제목과 러너 자리가 나는 순서대로 시작한다는 뜻을 쓴다.
- 처음 선택: 할당 전은 체크, 선행 티켓을 기다리면 체크와 안내, 지난 런 Failed·Canceled는 체크 안 함, 끝나지 않은 런은 목록에서 뺌, Done은 흐리게 두고 고를 수 없음.
- 각 하위 티켓은 자기 트래커 프로젝트의 Mapping으로 맡기고, Mapping이 없으면 고를 수 없다. 러너는 자동으로 고른다.
- 버튼은 "N개 할당하기"(0이면 비활성)와 "닫기"다.

### 할당

- 여러 티켓을 한 번에 받는 서버 함수를 더한다. 티켓마다 단일 할당과 같은 검사와 `assignRun`을 따로 해서 한 티켓의 실패가 다른 티켓을 되돌리지 않는다.
- 같은 요청이 두 번 들어와도 끝나지 않은 런 검사로 런이 두 번 생기지 않는다.
- 결과는 티켓별로 `role="status"`로 알리고 실패 이유는 단일 할당 문구를 다시 쓴다.
- 웹 `assignTicket`, worker 자동 할당, MCP는 바꾸지 않는다.

## 범위 밖

- MCP 일괄 도구, DB 변경, 러너를 직접 고르는 칸.

## 완료 조건

- [x] app: 티켓별 결과, 일부 실패, 처음 선택 규칙, Mapping 없음, 도는 런 제외, 중복 요청 시험
- [x] web: 상위 줄·패널 버튼과 N, 대화상자 체크 기본값, 결과 알림, 포커스 시험
- [x] e2e: 상위 이슈에서 하위 2개 할당 → 두 런 Queued, 부하 5회
- [x] 스크린숏: 상위 이슈 줄 버튼, 대화상자, 결과 알림

## 구현 결정

- 맨 위 상위 이슈는 묶음의 모든 하위 티켓을, 중간 이슈는 자기 아래 하위 티켓만 대상으로 한다. 하위가 있는 중간 이슈 자신은 대상에서 뺀다.
- 트래커에서 Canceled인 티켓은 Done처럼 흐리게 두고 고를 수 없다.
- 지난 런이 Succeeded인데 트래커에서 끝나지 않은 티켓은 고를 수 없다. 새 런은 그 티켓의 패널에서 시작한다.
- 상위 이슈 줄에 답하기·런 보기 할 일이 있으면 그 버튼을 먼저 두고, 일괄 할당은 패널에서 한다.
- 대화상자는 가상 스크롤로 줄이 사라져도 닫히지 않게 화면에 하나만 둔다.
- 상위 이슈 줄 버튼은 `Button`의 새 선택 속성 `outlined`로 테두리만 둔다. 패널 버튼은 회색 보조 버튼이다.
- 긴 제목은 저장 규칙처럼 상한으로 잘라 받아, 한 티켓의 제목 때문에 요청 전체가 거부되지 않게 한다.
- 대화상자에 저장소 칸이 없어, 라벨이나 지난 런으로 정해진 저장소를 그대로 보낸다. 그 저장소에 push할 러너가 없으면 풀릴 때까지 Queued로 기다린다.
- 취소된 선행 티켓이 있는 하위 티켓의 안내와 처음 선택은 운영자 결정에 없어 지금은 안내 없이 체크한다. 할당하면 런이 Queued에 멈추고 목록의 대기 표시로 드러난다.
