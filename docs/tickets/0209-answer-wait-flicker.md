# 0209 답 보낸 뒤 "답을 기다려요" 깜빡임

## 목표

질문에 답을 보낸 뒤(답이 에이전트에게 전해지기 전후) Dashboard 카드·패널·Runs에 "답을 기다려요"가 잠깐 다시 보였다가 사라진다는 0178 리뷰 뒤 후속이다. "답을 보냈어요"에서 (전달 뒤) 다음 상태로 한 번에 넘어가게 한다. 화면 문구는 바꾸지 않는다.

## 운영자 결정(2026-11-24)

- 먼저 지금 develop에서 재현한다. 재현되지 않으면 확인한 절차와 결과를 알리고 지시를 기다린다.
- 재현되지 않았고, 코드에서 찾은 틈을 worker에서 막기로 했다(코디네이터 지시). `apps/worker`의 답·거절 전달 표시와 Running 전환을 한 DB 트랜잭션으로 묶어 웹이 중간 상태를 읽지 못하게 한다. change_events 줄도 같은 트랜잭션에 넣는다. `packages/app` 상태 계산에는 방어를 더하지 않는다.

## 재현 절차와 결과

- 데모(`demo/src/main.ts --reset`, 가짜 러너와 실제 worker 루프 2초 주기, 웹 쓰기 뒤 worker 깨우기)를 띄우고 headless Chromium으로 Dashboard와 Runs를 두 탭에 열었다. 두 탭에 MutationObserver를 달아 DOM이 바뀔 때마다 상태 낱말, "답할 질문 N개", Runs 상황 문장, 대상 카드 글을 시각과 함께 남겼다.
- 질문 답 3번, Human Check "확인했어요" 1번, Permission 거절 1번을 Dashboard 패널에서 보냈다. 모두 "답을 보냈어요"(또는 "거절을 보냈어요")에서 Running으로 한 방향으로만 넘어갔고, "답을 기다려요"·"답하기"·"무엇을 기다리는지 아직 읽지 못했어요"로 되돌아간 프레임은 없었다. 재현되지 않았다.

## 찾은 틈

worker는 답을 전한 뒤 `markAnswerSent`(거절은 `markDenialSent`)와 `changeRunState(→running)`를 따로 썼다. 그 사이에 웹이 읽으면 런은 Waiting for Input인데 남은 입력이 없어, Runs는 "답을 기다려요"를 보이고 그 수에 넣고, Dashboard 카드는 "무엇을 기다리는지 아직 읽지 못했어요"를 보인다. 데모는 web과 worker가 한 프로세스라 끼어들 수 없지만, 배포(`ganger start`가 web과 worker를 따로 띄움)에서는 짧게 생길 수 있다.

## 고친 방법

- 바퀴 안에서 러너에 전한 답·거절은 메모리(`unmarkedAnswers`·`unmarkedDenials`)에만 두고, 상태를 바꾸는 바퀴에서는 전달 표시와 `changeRunState`를 한 트랜잭션으로 쓴다. 두 함수가 쓰는 change_events 줄도 그 안에 든다.
- 상태가 그대로인 바퀴는 전달 표시만 트랜잭션으로 쓴다. 런이 끝나는 바퀴는 끝을 쓴 뒤 전달 표시를 쓴다. 끝내기 전의 기다림(PR 읽기, 마지막 로그) 동안에는 표시하지 않은 답이 "답을 보냈어요"로 보인다.
- 트랜잭션 안에서 예외가 나면 둘 다 되돌아가고, 다음 바퀴는 러너에 다시 보내지 않고 둘을 함께 쓴다.

- 새 브라우저 시험은 더하지 않았다. 고친 곳이 worker의 DB 쓰기라 단위 시험으로 확인한다.
