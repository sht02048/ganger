# 0205 러너의 gh 계정 보이기

## 배경

에이전트는 러너의 git·gh 로그인으로 push하고 PR을 연다. Ganger 서버는 서버 기계의 GitHub 인증(0204에서 gh 우선)으로 PR을 읽는다. 둘이 볼 수 있는 저장소가 어긋나면 서버가 PR을 읽지 못한다. 운영자가 러너에서 어느 계정으로 로그인했는지 Runners 화면에서 바로 보게 한다.

## 운영자 결정 (2026-11-23)

1. 러너 확인(ssh)에서 러너의 `gh auth status`를 읽어 로그인한 계정을 저장한다. 계정이 여럿이면 모두, 사용 중인 계정을 표시한다. gh가 없으면 "gh 없음", 로그인이 없으면 "로그인 안 됨"이다.
2. 토큰 값은 읽지도 저장하지도 않는다. 출력에서 계정 이름만 꺼내고, 토큰을 보이는 옵션을 쓰지 않는다.
3. 러너 상세 패널에 "GitHub (gh)" 구역으로 보인다. 문제 표시는 하지 않는다(정보만).
4. "러너는 A 계정, 서버는 B 계정이에요" 진단은 0204가 머지된 뒤에 한다. 0204가 이 티켓보다 먼저 머지되지 않았으므로 후속으로 남긴다.
5. `runners` 표에 `gh_accounts`(JSON), `gh_accounts_read_at` 열을 더한다(운영자 승인 2026-11-23).

## 구현 메모

- 0191의 사용량·부하 고정 스크립트 끝에 gh 구역을 더해 같은 ssh 연결, 같은 주기(5분)에 읽는다. 스크립트는 고정 문자열이다.
- ssh 비대화형 셸의 PATH에 gh가 없을 수 있어 `command -v gh` 다음에 Homebrew 경로(`/opt/homebrew/bin`, `/usr/local/bin`)를 차례로 본다. Linuxbrew 경로(`/home/...`)는 서버 배포물 검사가 빌드 기계 경로로 막고, 리눅스 러너는 1단계 밖이라 넣지 않는다.
- 러너 쪽에서 `Token:`이 든 줄을 지워 보내고, 파서는 계정 줄의 호스트·이름과 `Active account` 줄만 읽는다. 저장할 때 스키마로 다시 걸러 다른 값이 섞이지 않는다.
- 예전 gh(계정 하나 형식, `Logged in to HOST as LOGIN`)는 호스트마다 계정이 하나라 사용 중으로 본다.
- gh가 시간 제한까지 끝나지 않아도 먼저 끝난 부하 값은 버리지 않는다.
- 웹 Runners 화면에만 싣고 MCP 러너 조회 응답은 그대로 둔다(0191과 같다).
