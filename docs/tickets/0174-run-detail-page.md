# 0174 런 상세 페이지 정리

운영자(2026-11-22)가 런 상세가 복잡하다고 짚었다. 패널은 "PR의 CI가 실패해서 확인이 필요해요"라고 하는데 상세는 같은 런에 "할 일이 없어요"라고 했고, PR 정보가 상태 줄·버튼·런 정보 16줄에 흩어졌고, 런 정보 카드가 터미널을 아래로 밀었고, 끝난 런의 노란 주 버튼이 "이어서 맡기기"였다.

## 운영자 결정 (2026-11-22)

- **머리.** ‹ Runs, 키 · 프로젝트 · 러너 · 브랜치, 제목, 상태 알약(영어 유지)과 "N 끝남 · N 걸림 · 에이전트 결과" 한 줄. 오른쪽에 보조 버튼(이어서 맡기기, 멈추기/재개, 런 취소, 워크트리 지우기). 동작과 확인 대화상자는 그대로다.
- **처리할 일 띠.** Runs 패널과 같은 문장을 맨 위에 둔다. 노란 주 버튼은 그 상황에서 해야 할 일에만 쓴다. 처리할 일이 없으면 띠 없이 조용한 한 줄만 둔다. 판단은 공용 함수 `runNextStep`이 한다(선행 PR #220).
- **왼쪽 열.** 입력 대기·선행 티켓 대기·마지막 출력·시작 오류, PR 구역(CI·충돌·base, 검사 링크, GitHub 링크, 읽은 때), 지나온 일(완료 보고는 종료 항목 안), 에이전트에게 보내기.
- **오른쪽 열.** 런 정보 4줄(러너 링크, 에이전트·모델, 대기·실행, 워크트리)과 그 안에 접은 받은 지시서, 터미널 끝부분, 같은 티켓의 다른 런.

## 완료 조건

- 처리할 일 문장과 주 버튼: PR CI 실패, 충돌, Question, Permission, 멈춤, 끊김, 실패, 없음.
- 레이아웃: PR 구역 한 곳, 완료 보고가 지나온 일 안, 런 정보 줄 수, 러너 링크, 받은 지시서 접힘.
- 기존 run-detail 시험과 e2e를 새 구조에 맞춘다. 지워지는 시험이 지키던 동작은 대응표를 PR 본문에 적는다.
- 스크린숏: 끝난 런(PR CI 실패), Running, Question 대기, 좁은 화면.
