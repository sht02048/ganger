# 0202 흔들리는 Settings 브라우저 시험 지우기

## 목표

`e2e/src/settings.test.ts`의 시험 4개가 PR과 상관없이 CI에서 함께 실패해 `check`를 막는다. 운영자 결정(2026-11-20)대로 고치지 않고 지우고, 잃은 확인 범위를 여기에 남긴다.

지우는 시험:

- 「Settings 한 페이지(브라우저, 0119) > 프로젝트를 넣으면 새 줄로 포커스가 가고, 상세에서 빼면 Settings 로 돌아온다」
- 「Settings 한 페이지(브라우저, 0119) > 프로젝트 상세에서 저장하지 못한 저장소 초안이 있으면 Settings 로 옮기지 않고 알린다」
- 「Settings 폼과 도움말(브라우저, 0119 리뷰 후속) > 넣을 트래커 프로젝트 목록은 Escape 로 닫고 + 넣기로 포커스가 돌아온다」
- 「Settings 폼과 도움말(브라우저, 0119 리뷰 후속) > + 넣기를 누르면 넣을 프로젝트 목록의 첫 버튼으로 포커스가 간다」

## 실패 근거

- PR #257(0199, Settings를 건드리지 않음)의 CI run 45160538915 첫 시도(head `ff772789`), 잡 `browser (1)`에서 위 4개가 실패했다. 다시 돌린 두 번째 시도에서는 통과했다.
- PR #235(0187)의 CI run 45038852543 첫 시도(head `caf24849`), 잡 `browser (1)`에서도 같은 4개가 같은 모양으로 실패했고, 두 번째 시도에서 통과했다. 0187 때 흔들린 시험은 이 4개 모두다.
- 두 번 모두 실패 모양이 같다.
  - 첫 시험: 「넣기」를 누른 뒤 포커스가 새 API 줄로 가지 않았다(`expect.poll(focused).toContain("API")`가 `null`로 끝남).
  - 둘째 시험: 넣을 목록에서 「넣기」 버튼을 30초 동안 찾지 못했다.
  - 셋째·넷째 시험: 「+ 넣기」를 누른 뒤 포커스가 「넣기」가 아니라 「닫기」에 있었다.
- 같은 파일은 로컬에서 단독으로 돌리면 통과한다.

### 실패가 이어진 까닭

시드에는 넣을 수 있는 트래커 프로젝트가 API 하나뿐이다(`e2e/src/settings-adapters.ts`). 첫 시험은 API를 넣고 포커스를 확인한 뒤에 API를 뺀다. 포커스 단언에서 멈추면 API를 빼지 못해 DB에 남는다. 그러면 뒤 시험이 연 넣을 목록에는 넣을 프로젝트가 없어 「넣기」 버튼이 없고, `FocusFirst`는 첫 버튼인 「닫기」로 포커스를 준다. 그래서 둘째·셋째·넷째 시험은 첫 시험의 실패를 이어받아 실패한 것이다. 처음 흔들린 것은 첫 시험의 「넣은 뒤 새 줄로 포커스」 하나다. 넷 모두 같은 시드 상태를 나눠 쓰므로 함께 지운다.

## 잃은 확인 범위

지운 시험은 실제 브라우저에서 Settings 「프로젝트」 구역의 「+ 넣기」 → 넣을 목록 → 「넣기」 → 새 줄 포커스 흐름, Escape로 목록 닫기와 포커스 되돌림, 프로젝트 상세에서 빼고 Settings로 돌아오기, 프로젝트 상세의 저장하지 못한 저장소 초안으로 이동 막기를 봤다.

### 이미 지키는 부분

- 트래커 프로젝트를 Workspace에 넣는 서버 동작과, 다른 Workspace에 있는 프로젝트는 넣을 목록에서 고를 수 없게 그리는 일: `apps/web/src/settings/settings.test.tsx`의 「트래커 프로젝트는 Workspace 하나에만 > 이미 다른 Workspace 에 묶인 트래커 프로젝트는 고를 수 없다」. `ProjectCandidates`를 그려 「넣기」 버튼이 꺼지고 켜지는지 본다.
- 프로젝트를 빼면 함께 지워질 Mapping과 Queued 런 수, 빼도 런 기록이 남는 일: 같은 파일의 「빼기 전에 함께 지워질 Mapping 과 그 Queued 런 수를 알고, 빼도 런 기록은 남는다」.
- 브라우저에서 프로젝트 상세의 「빼기」 → 확인 → Settings로 돌아와 목록에서 빠지는 일: `e2e/src/settings-query.test.ts`의 「프로젝트 상세에서 프로젝트를 빼면 찾을 수 없음 화면 없이 Settings 로 돌아가고 목록에서 빠진다」.
- 펼친 편집 칸을 열면 첫 칸으로 포커스가 가고, Escape로 닫으면 연 버튼으로 포커스가 돌아오는 같은 `useInlineEdit`·`FocusFirst` 흐름: `e2e/src/settings.test.ts`의 「트래커 연결 상세의 webhook 켜기(브라우저, 0130) > 주소를 확인한 뒤 secret 을 넣고 켜면 기다리고, 가짜 webhook 을 받으면 켜짐으로 바뀐다」(주소 칸 포커스, Escape 뒤 「바꾸기」 포커스)와 `e2e/src/log-settings.test.ts`의 「진단 묶음을 펼쳐 만들면 가린 zip을 내려받고 결과를 알린다」(`FocusFirst onEscape`로 닫은 뒤 「진단 묶음 만들기」 포커스).
- 고친 값이 남아 있으면 다른 화면으로 옮기지 않고 `unsavedBlocked` 알림을 보이는 이동 막기(`NavigationGuard`·`useUnsavedHold`): `e2e/src/settings.test.ts`의 「고친 값이 남아 있으면 다른 화면으로 옮기지 않고 그 줄을 보인다」. Settings 한 페이지의 줄 편집으로 확인한다.
- 저장소 초안을 더하고 빼는 계산: `apps/web/src/settings/mapping-draft.test.ts`.

### 아무도 지키지 않는 부분

- 넣을 목록에서 「넣기」로 프로젝트를 넣은 뒤 목록이 닫히고 포커스가 새 프로젝트 줄 링크로 가는 일(`ProjectsSection`의 `focusKey`). 처음 흔들린 바로 그 단언이다.
- 「+ 넣기」를 누르면 넣을 목록의 첫 「넣기」 버튼으로 포커스가 가는 일.
- 넣을 트래커 프로젝트 목록을 Escape로 닫으면 「+ 넣기」로 포커스가 돌아오는 일. 같은 `FocusFirst onEscape`는 진단 묶음에서만 브라우저로 본다.
- 브라우저에서 Settings 화면으로 프로젝트를 넣어 새 줄이 생기는 일. 넣는 흐름 전체를 보는 브라우저 시험이 없다.
- 프로젝트 상세(`PROJECT_EDITOR_SELECTOR`, `#repo`)에 저장하지 못한 저장소 초안이 있을 때 「Settings」 돌아가기를 막고 알리는 일, 한 번 더 누르면 옮겨 가는 일. 이동 막기는 Settings 한 페이지의 줄 편집으로만 본다.

## 남은 의문

첫 시험에서 「넣기」 뒤 포커스가 새 줄로 가지 않은 까닭은 재현하지 않아 확인하지 못했다. `focusKey` 효과는 링크가 아직 그려지지 않았으면 다음 `workspace` 변화 때 다시 찾는데, CI 부하로 다시 읽기가 늦어 제한 시간을 넘겼는지, 다시 읽은 뒤에도 효과가 다시 돌지 않는 제품 쪽 경쟁 상태인지는 가리지 못했다. 다시 시험을 더한다면 시험마다 시드를 되돌려 한 시험의 실패가 다음 시험으로 번지지 않게 해야 한다.
