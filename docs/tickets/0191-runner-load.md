# 0191 러너 부하(CPU·메모리·GPU) 읽고 보여 주기

## 배경

운영자 요청(2026-11-23): 러너의 부하 상황을 보고 싶다. Ganger는 이미 ssh로 러너에 붙어 공급자 사용량을 주기적으로 읽는다. 같은 연결에서 가벼운 명령을 더 돌려 CPU·메모리·GPU를 읽는다. 러너에 새 프로그램을 설치하지 않는다.

## 운영자 결정 (2026-11-23)

1. 읽는 것은 CPU·메모리·GPU 셋이다. 디스크는 뺀다.
2. 공급자 사용량 읽기 주기(5분)에 같이 읽고 ssh 연결을 늘리지 않는다. 화면에 읽은 때를 함께 보인다.
3. CPU는 1분 평균 부하 ÷ 코어 수, 메모리는 쓴 양/전체와 메모리 압박, GPU는 사용률이다. 관리자 권한 없는 명령만 쓰고, 읽지 못한 값은 "없음"이다. 리눅스는 `/proc/loadavg`, `nproc`, `/proc/meminfo`, `nvidia-smi`로 읽을 수 있는 만큼만 읽는다.
4. Runners 목록 맨 오른쪽에 "부하" 칸, 러너 상세의 자리와 사용량 사이에 "부하" 구역, 머리 요약에 부하가 높은 러너를 더한다.
5. Dashboard는 보통이면 그대로이고, 높으면 러너 줄 둘째 줄을 이유로 바꾸고 러너 문제 카드에 묶음과 안내를 더한다.
6. 높음은 CPU 90% 이상이 5분 넘게 이어짐, 메모리는 macOS 메모리 압박 높음(리눅스는 사용 90% 이상)이다. GPU는 알리지 않는다. Settings로 바꾸지 않는다.
7. 기록·그래프는 없다. 할당 규칙과 Queued 이유는 바꾸지 않는다.

## 구현 메모

- `runners` 표에 `load`(JSON), `load_read_at` 열을 더했다(운영자 승인 2026-11-23). 되돌리는 법은 PR 본문에 적는다.
- 부하 명령과 `orca account list`를 고정 스크립트 하나로 묶어 ssh 연결 하나로 돌린다. orca 경로는 위치 인자로만 넘긴다.
- macOS 메모리 압박은 `kern.memorystatus_vm_pressure_level`로 읽는다. 1은 보통, 2·4는 높음이다.
- 읽는 간격이 10분을 넘으면 CPU가 이어졌다고 보지 않고, 10분 넘게 새로 읽지 못한 값은 높음으로 알리지 않는다.
