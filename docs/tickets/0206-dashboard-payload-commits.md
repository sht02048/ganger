# 0206 Dashboard 응답에서 커밋 목록 빼고 「PR」 탭을 열 때 받아 오기

0200이 Dashboard 응답(`HomeRun`)에 모든 런의 PR 커밋 목록(PR 당 최대 250줄)을 실었다. 런과 PR이 쌓이면 Dashboard 응답과 실시간 갱신 때 다시 받는 양이 커진다(0200 PR 본문의 남은 위험).

## 운영자 결정 (2026-11-24)

1. Dashboard 응답에는 커밋 수와 마지막 커밋 시각만 싣는다(「▸ 커밋 N개 · 마지막 n분 전」에 필요한 값).
2. 커밋 목록은 런 패널의 「PR」 탭에서 커밋 줄을 펼칠 때 그 런 하나만 서버 함수로 받아 온다. 저장된 PR 신호에서 읽고 GitHub를 새로 부르지 않는다.
3. 받아 오는 동안 펼친 자리에 짧은 로딩을 두고, 실패하면 "커밋을 불러오지 못했어요 · 다시 시도"를 둔다.
4. 화면 모양은 0200 그대로다. MCP와 모바일 v1 응답은 바꾸지 않는다.
5. 줄어든 응답 크기를 데모 기준 전후 숫자로 PR 본문에 적는다.

## 고칠 곳

- `packages/app/src/home`: `HomePullRequest`의 커밋 목록을 커밋 요약(수, 마지막 커밋 시각)으로 바꾸고, 런 하나의 커밋 목록을 읽는 로더를 둔다.
- `apps/web/src/home`: 「PR」 탭이 펼칠 때 서버 함수로 커밋을 받아 온다.
- `packages/ui` `CommitHistory`: 펼침 알림과 로딩·실패 줄을 선택 속성으로 넓힌다.

## 완료 조건

- [ ] Dashboard 응답에 커밋 배열이 없다는 시험.
- [ ] 펼칠 때 한 번만 받아 온다는 시험(접었다 다시 펼쳐도 다시 부르지 않음).
- [ ] 로딩, 실패, 다시 시도 시험.
- [ ] 펼친 모양이 0200과 같다는 시험(순서, 줄임표와 전체 글, 새 탭 링크).
- [ ] 데모 기준 응답 크기 전후 숫자를 PR 본문에 적는다.
