# 0181 앱 안 이동과 돌아가기 다시 짜기

## 배경

운영자 보고(2026-11-22): Tickets에서 런 보기로 런 상세에 가면 머리에 `‹ Runs`만 있어 왔던 곳으로 돌아갈 수 없다. 앱 안 링크 다수가 일반 `<a>`라 누를 때마다 문서 전체를 다시 불러오고, 앱 어디에도 history 돌아가기가 없다.

## 운영자 결정 (2026-11-22)

1. 런 상세 머리 왼쪽 위를 "왔던 곳으로 돌아가기"로 바꾼다. 보이는 글자는 `‹` 하나이고, 접근 이름과 툴팁은 출발 화면을 따른다("Tickets로 돌아가기" 등). 앱 안 이동 기록이 있으면 history back으로 돌아가 출발 화면의 거르기·고른 줄·스크롤이 그대로다. 기록이 없으면 `/runs?ws`로 가고 이름은 "Runs로 돌아가기"다.
2. 앱 안 링크를 모두 앱 안 이동으로 바꾼다. href는 유지하고 일반 클릭만 라우터로 옮기며 ⌘·Ctrl·Shift·가운데 클릭은 브라우저 기본을 따른다. Dashboard→Runners 링크에 `ws`를 붙인다.
3. Tickets의 런 보기·답하기·패널 런 목록은 런 상세로 바로 간다. 답하기는 질문 구역이 바로 보이게 한다. "Runs에서 모두 보기"는 그대로 Runs로 간다.
4. Settings 하위(프로젝트·연결·MCP)는 고정 부모 Settings로 가되 같은 `‹` 모양으로 맞추고, 돌아가면 그 줄이 보이게 스크롤한다.
5. Settings "Workspace 만들기"로 들어간 온보딩에 같은 모양의 Settings 돌아가기를 더한다. 처음 온보딩에는 없다.
6. 데스크톱 앱 메뉴에 뒤로(⌘[)·앞으로(⌘])를 더한다.

## 결정

- 출발 화면은 navigate state의 `backOrigin`에 남기고, 그 문서에서 만든 기록인지 `backDocument`로 가린다. 새로고침해도 `__TSR_index`가 그대로 남아 `useCanGoBack`만으로는 기록 없음을 알 수 없고 서버 렌더와 어긋난다.
- 앱 안 링크는 `_app` 레이아웃의 `InAppLinks` 한 곳에서 받아 라우터 이동으로 바꾼다. 링크마다 고치지 않아 앞으로 더하는 일반 `<a>`도 같은 규칙을 따른다.
- Workspace를 바꾼 런 상세나 출발 화면을 남기지 않은 이동의 `‹`는 Runs로 간다.
