# 0168 흔들리는 Runs 움직임 시험 지우기

## 목표

`e2e/src/screen-motion.test.ts`의 「Runs 움직임(브라우저, 0153) > Workspace 를 바꿨다 돌아오면 그사이 바뀐 상태와 새 행이 움직이지 않는다」가 PR과 상관없이 CI에서 실패해 `check`를 막는다. 운영자 결정(2026-11-20)대로 고치지 않고 지우고, 잃은 확인 범위를 여기에 남긴다.

## 실패 근거

- `develop` 7f76503의 CI run 44906031435, 잡 `browser (2)`에서 실패했다.
- 같은 시험이 `develop` b558153(run 44890431131), PR #209(0163, run 44914118553), PR #210(0162, run 44914311561)에서도 실패했다.
- 실패는 시간 초과가 아니라 `expectQuiet`의 단언 실패다. 돌아온 뒤 움직임 호출 4번이 기록됐다. 상태가 바뀐 행의 알약 커짐 1번과 새 행의 들어오기 3번(`gridTemplateRows`·`opacity`, `transform`, `opacity`)이다.

## 할 일

- [x] 그 시험 하나만 지운다. 같은 파일의 다른 시험은 그대로 둔다.
- [x] 쓰지 않게 된 도우미·import를 확인한다. 그 시험이 쓰던 도우미는 모두 다른 시험도 써서 지울 것이 없다.
- [x] 잃은 확인 범위와 단위 시험이 덮는지 적는다.

## 잃은 확인 범위

Runs에서 Workspace를 바꿨다 돌아왔을 때, 나가 있는 동안 상태가 바뀐 행의 알약과 새로 생긴 행이 움직이지 않는지를 이제 어떤 시험도 확인하지 않는다.

같은 동작을 덮는 단위 시험은 없다. `packages/ui/src/motion-plan.test.ts`는 움직임 계획만 보고 `MotionList`의 `resetKey` 처리를 보지 않는다.

가까운 확인으로 남는 브라우저 시험은 셋이고, 모두 잃은 범위를 대신하지 못한다.

- 「Dashboard 움직임(브라우저, 0153) > Workspace 를 바꿨다 돌아오면 그사이 생긴 알약이 움직이지 않는다」: 같은 전환에서 이미 있던 카드의 알약만 Dashboard에서 본다. 새 행과 Runs 화면은 보지 않는다.
- 「Dashboard 움직임(브라우저, 0153) > 전체에서 한 Workspace 로 바꾸며 상태가 달라진 카드도 움직이지 않는다」: 전체에서 한 Workspace로 바꾸는 경우를 Dashboard에서만 본다.
- 「Runs 움직임(브라우저, 0153) > 첫 렌더와 필터 바꾸기에서는 움직이지 않는다」: Runs의 목록 바꾸기를 보지만 그사이 데이터가 바뀌는 경우는 보지 않는다.

## 남은 의문

실패 기록의 움직임은 알약 커짐 1행과 새 행 들어오기 1행으로, 시험이 움직이면 안 된다고 본 두 행의 모양과 맞다. 로그에는 Run id만 있어 두 행과 직접 맞춰 보지는 못했다. 그래서 시험만의 문제가 아니라 돌아온 직후 화면이 실제로 움직이는 제품 쪽 경쟁 상태일 수 있다. 재현하지 않았고 원인은 확인하지 않았다.
