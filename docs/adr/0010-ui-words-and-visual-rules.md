# UI 낱말과 시각 규칙

운영자가 구현된 화면이 딱딱하다고 해 pen.dev로 시안을 다시 만들었고, 시안 B(왼쪽 아이콘 레일 + 손댈 일 카드 + 오른쪽 실시간 흐름)를 골랐다. 시안과 지금 화면을 점검하니 규칙이 16가지 깨져 있었다. 같은 상태를 한국어와 영어로 섞어 부르고(Waiting for Input의 "입력 기다림"과 Human Check), 같은 것을 여러 이름으로 부르고, 상태 모양과 색이 화면마다 다르고, 주 버튼이 한 화면에 여럿이고, 시간 표기가 7종, 제목 규칙이 3종이고, 메뉴에 Settings·Workspace가 빠져 있었다. 운영자가 2026-11-18에 아래 규칙을 정했다(Q14~Q21).

## 낱말

1. **상태 이름은 GLOSSARY의 영어 용어 그대로 쓴다.** 런 상태 Queued·Running·Waiting for Input·Paused·Disconnected, 요약 결과 Succeeded·Failed·Canceled(아래 0145 갱신. 앞서 Merged·Human Check·Failed·Canceled), 러너 Online·Offline. To do 종류는 Question·Permission·Failed·Disconnected다(0145 갱신으로 Human Check가 빠졌다). 운영자가 정한 종류 목록에는 Failed가 없었지만, Failed 런은 지금도 To do에 오르고(스펙 Q82.9) 색 규칙에도 있어 종류에 넣었다. 러너 문제는 Runner Issue로 부르고 세부 원인(GitHub 인증 깨짐, Offline 등)은 설명 문장으로 쓴다. Runner Issue는 To do에 올리지 않고, Dashboard에서는 오른쪽 Runners 열에 보인다(아래 갱신). Runner Issue에 Offline 러너를 넣는 것은 운영자 결정(규칙 1의 "러너 인증 깨짐·Offline 등")이고 0049에서 적용했다.
2. **설명 문장·버튼·안내는 한국어 해요체로 쓴다.** "모두"처럼 상태가 아닌 개념 낱말도 한국어로 둔다. 예외로 Dashboard 칸·열 이름(Queued·Running·Done·Runners)은 메뉴·화면 이름처럼 영어로 쓴다(아래 0100 갱신). 에이전트 결과와 PR 상태의 값(완료 보고(성공), 병합됨 등)은 상태 이름이 아니라 런이 어떻게 끝났는지 설명하는 값이라 한국어 그대로 둔다.
3. **메뉴·화면 이름은 Dashboard·Tickets·Runs·Runners·Stats·Settings다.** 온보딩 단계 이름은 Tracker·GitHub·Runner·Workspace·Mapping이다.

## 모양

4. **상태는 "점 + 이름" 알약 하나로만 보인다.** 모든 화면에서 같은 컴포넌트를 쓴다. 예외는 Dashboard다. 칸반 카드는 To do인 카드에만 꼬리표 알약(To do 종류 이름)을 달고, 나머지 카드는 칸 이름이 상태를 대신하거나(Queued·Running) 상태 이름을 글로 쓴다(Done의 처리할 일 없이 끝난 카드). Runners 열의 행은 알약 대신 상태 점으로 상태를 보인다(아래 0068·0100 갱신). 어느 화면이든 행 하나에 상태는 하나만 보인다.
5. **색 하나에 뜻 하나다.**

   | 색   | 뜻             | 상태                                        |
   | ---- | -------------- | ------------------------------------------- |
   | 보라 | 사람이 답·허용 | Question, Permission, Waiting for Input     |
   | 청록 | 사람이 확인    | Human Check(0148 갱신)                      |
   | 빨강 | 문제           | Failed, Disconnected, Runner Issue, Offline |
   | 초록 | 진행·정상      | Running, Online                             |
   | 파랑 | 성공           | Succeeded                                   |
   | 회색 | 대기·멈춤      | Queued, Paused, Canceled                    |

   강조색(티켓 [0080](../tickets/0080-apply-brand-to-app-ui.md)): 상태가 아닌 강조는 Ganger Yellow `oklch(0.84 0.15 75)` 하나다(`accent*`). 주 버튼, 링크, 고른 탭·레일 항목 표시, 포커스 링, 로고 취구와 마스코트 모자에 쓴다. 노랑 바탕 위 글자는 Ink다. 바탕·면은 Ink `oklch(0.14 0 0)`에서 밝기만 바꾼 무채색, 글자는 Paper `oklch(0.97 0.003 85)`에서 밝기만 내린 따뜻한 무채색이다. 상태 색은 강조색과 색상(hue)이 40° 넘게 떨어진다. 앞서 0077은 노랑을 Human Check 색과 겹치지 않게 그림 안에만 두었으나, 0080에서 Human Check가 노랑을 내놓고 청록이 되어 이 예외를 강조색 규칙으로 바꿨다. 마스코트는 화면이 장난스러워지지 않게 상태를 나타내는 자리 곁에 두지 않는다.

6. **노란 주 버튼은 화면 전체에서 주 행동 하나에만 쓴다.** 카드마다 하나가 아니다(Q18). Dashboard 카드의 행동(답하기, PR 보기)은 보조 버튼이다. 레이어(팝오버·대화상자·오른쪽 패널) 안의 주 행동 하나는 노란 주 버튼을 쓸 수 있다. 질문 선택지는 버튼이 아니라 하나를 고르는 라디오 항목이고, 모두 같은 모양이며 추천 선택지처럼 칠하지 않는다. 고르기만 해서는 보내지 않고, 고른 뒤 "보내기"를 눌러야 보낸다. 위험 행동(취소, 거절)은 빨간 글자 보조 버튼이다.
7. **시간 표기는 세 가지다.** 진행 중인 것은 경과("25 min"), 지난 일은 상대 시간("25 min ago", 1분 안이면 "Just now", 하루가 넘으면 날짜), 타임라인은 시각("10:45")이다(2026-11-21 갱신, 티켓 0162). 비율은 띄우지 않고 "2/2"로 쓴다.
8. **화면 제목은 메뉴와 같은 화면 이름이고, 콘텐츠 맨 위 한 줄 머리에 요약 문장과 나란히 둔다.** 제목이 왼쪽, 요약 문장이 그 옆, 그 화면의 머리 행동이 오른쪽이다. Dashboard와 Stats의 결론 문장도 제목이 아니라 요약 문장이다(아래 0113 갱신. 앞선 0068 갱신의 결론 제목을 바꾼다).
9. **티켓은 어디서나 "회색 키 + 제목"으로 보인다**(ACME-1 결제 실패 재시도).
10. **둥글기는 카드 12px, 버튼·행·입력 8px, 알약 6px이다.** 영역은 선이 아니라 면(배경색)으로 나눈다. Dashboard에서는 칸반 칸(Queued·Running·Done)이 면이 있는 카드이고 그 안의 런 카드가 한 단계 밝은 면이며, 오른쪽 Runners 열은 면 없이 제목과 목록만 둔다(아래 0100 갱신).
11. **레일 맨 위에 Workspace 바꾸기, 그 아래 메뉴, 맨 아래에 Settings와 제품 기호(취구가 노란 호루라기)를 둔다(아래 0113 갱신. 전에는 제품 기호가 맨 위였다).** Runners 아이콘에 문제 개수 점을 단다(티켓 [0077](../tickets/0077-ganger-logo-and-icon.md)에서 기호를 더했고, [0080](../tickets/0080-apply-brand-to-app-ui.md)에서 한 색판을 노란 취구 판으로 바꿨다).

**갱신(2026-11-18, 운영자 결정, 티켓 [0059](../tickets/0059-dashboard-decision.md)).** UI 리뷰 후속(0050~0057) 뒤 운영자가 Home의 문제로 티켓 런과 러너 문제가 한 목록에 섞이는 점, 카드가 쓸데없이 긴 점, 오른쪽 위 개수 타일이 잘 안 보이고 위치가 이상한 점을 짚었다. 시안 몇 차례 끝에 아래로 바꿨고, 위 1·2·3·6번과 "바뀌는 화면"에 반영했다. 화면 적용은 티켓 [0060](../tickets/0060-dashboard-screen.md)이 한다.

- 화면 이름은 Home이 아니라 Dashboard다(3번).
- "손댈 일"은 To do로 바꾼다. 러너 문제(Runner Issue)는 To do에서 빼 Dashboard 오른쪽 Runners 구역으로 옮긴다(1번).
- "지금 일어나는 일" 흐름은 다른 구역과 겹쳐 뺀다. 그 자리에 오늘 끝난 런(Done today)을 둔다. 오른쪽 위 개수 타일도 뺀다.
- 질문은 행 안에 펼치지 않고 "답하기"로 여는 레이어에서 답한다. 선택지는 고르는 라디오 항목이고, "보내기"(레이어 안의 주 버튼)를 눌러야 보낸다(6번). Run 상세의 질문 카드는 0060 범위 밖이라 아직 선택지를 누르면 바로 보내는 보조 버튼이다. 이 규칙으로 바꾸는 일은 따로 티켓으로 한다.
- 앞선 문서([ADR 0004](0004-agent-merges-its-own-pr.md)·[0009](0009-run-via-orca-orchestration.md), [1단계 스펙](../spec/0001-phase-1.md), `design/prototype/README.md`, 끝난 티켓)의 "손댈 일"·"홈"·"Home"은 그때의 기록이다. 지금 낱말은 To do와 Dashboard다. Dashboard 밖 화면의 메시지 파일에 남은 "손댈 일"(Tickets 탭, Canceled 설명, 디자인 시스템 미리보기 등)도 0060 범위 밖이라, To do로 바꾸는 일은 Run 상세 질문 카드와 함께 따로 티켓으로 한다.

**갱신(2026-11-18, 운영자 결정, 티켓 [0068](../tickets/0068-v2-screens-decision.md)).** 운영자가 `pnpm dev`로 구현된 화면을 리뷰하고 Dashboard·Tickets·Runners·Stats의 문제를 짚었다. Dashboard는 카드 넷이 같은 모양에 제목이 작고, To do가 진한 알약 열한 줄이고 Failed 일곱 줄이 같은 문장을 되풀이했다. Tickets는 필터 이름에 한국어·영어와 기준이 섞이고, 같은 값만 되풀이하는 열이 있고, 페이지가 통째로 스크롤돼 머리와 필터가 사라졌다. Runners는 카드 한 장에 모든 것이 들어가 높이가 제각각이고 상태 알약이 두 개씩 붙었다. Stats는 숫자 칸이 4+1로 끊기고, 결론 문장이 없고, 실패 이유가 내부 조합 이름이고, 늘 붙은 오른쪽 패널이 화면을 좁혔다. 아래로 바꿨고, 위 4·8·10번과 "ADR 0007과의 관계"에 반영했다. 화면 적용은 티켓 [0069](../tickets/0069-dashboard-v2.md)(Dashboard), [0070](../tickets/0070-tickets-v2.md)(Tickets), [0071](../tickets/0071-runners-v2.md)(Runners), [0072](../tickets/0072-stats-v2.md)(Stats)가 한다.

- **화면 제목(8번).** Dashboard와 Stats는 결론 문장("처리할 일이 3개 있어요", "끝난 런 40개 중 70%를 에이전트가 병합까지 끝냈어요")을 제목으로 쓰고, 화면 이름은 그 위의 작은 메타 줄에 둔다. 다른 화면은 화면 이름 + 요약 한 줄을 그대로 따른다.
- **Dashboard.** To do를 하는 일로 묶는다. 답이 필요해요(Question, Permission, 보라), 확인해 주세요(Human Check, 청록), 멈췄어요(Failed, Disconnected, 빨강)다. 묶음 머리의 색 점과 이름이 행마다의 상태 알약을 대신하고(4번의 예외), 되풀이되는 설명은 묶음 머리에 한 번만 두고, 묶음 안의 모든 종류에 맞는 문장으로 쓴다(Disconnected 런은 끝나지 않아 다시 할당할 수 없다). 묶음 이름은 To do 종류 이름을 대신하지 않는다. 종류 이름(Question 등)은 GLOSSARY와 코드의 낱말로 남고, 묶음 이름은 화면에서 종류 여럿을 하는 일로 모아 부르는 설명 문장이다. To do만 면이 있는 카드이고, In progress와 오른쪽 열(Runners, Done today)은 면 없이 제목과 목록만 둔다(10번). 이 구역들의 행은 알약 대신 상태 점 하나로 상태를 보인다(4번의 예외).
- **Runners.** 러너 카드를 목록 + 오른쪽 상세 패널([ADR 0007](0007-ui-list-detail-panel.md))로 바꾼다. 행에는 상태 알약 하나만 보이고, 문제 있는 러너(Runner Issue, Offline 포함)가 Online 러너보다 위에 온다. 알약은 Offline 러너면 Offline, 그 밖의 Runner Issue 러너면 Runner Issue, 문제가 없으면 Online이다. 해결 안내와 확인 항목, 남은 워크트리는 고른 러너의 패널에 둔다.
- **Tickets 필터.** 모두 / 할당할 수 있음 / 처리할 일 / 진행 중 / 끝남이다. 모두 한국어 낱말이고, 기준은 하나다. 운영자가 그 티켓으로 무엇을 할지(맡길지, 손댈지, 기다릴지, 볼 일이 없는지)에 답한다. 각 낱말의 뜻은 GLOSSARY의 Tickets 필터를 따른다. 키·제목 검색을 둔다. 화면 머리·필터·열 이름은 고정하고 목록만 스크롤한다. 0059 갱신에서 따로 티켓으로 하기로 한 메시지 파일의 "손댈 일"(Tickets 탭, Canceled 설명 등)은 이름 자리(구역·종류 이름)면 영어 To do로, 필터 이름과 문장 안이면 처리할 일로 바꾼다(GLOSSARY To do·Tickets 필터).
- **Stats.** 오른쪽 상세 패널을 없앤다. 기간(7일·14일·30일)을 고르고 앞 기간과 비교한다. 실패 이유는 에이전트 결과·PR 상태 조합 이름 대신 말로 쓴다(예: "에이전트가 실패를 보고했어요", "최대 실행 시간을 넘겼어요"). 2번의 "에이전트 결과와 PR 상태의 값은 한국어 그대로 둔다"는 그 값을 보일 때의 규칙이고, Stats의 실패 이유는 값 이름 대신 문장으로 쓴다.

**갱신(2026-11-18, 운영자 결정, 티켓 [0080](../tickets/0080-apply-brand-to-app-ui.md)).** 운영자가 브랜드 세 색(Ink·Paper·Ganger Yellow)을 앱 화면 전반에 쓰기로 하고, 노랑을 강조색으로 골랐다. 위 5·6·11번과 이유, Consequences에 반영했다.

- 강조색(주 버튼, 링크, 고른 탭·레일 항목, 포커스 링)은 파랑에서 Ganger Yellow로 바뀐다. 고른 행은 티켓 0091부터 노랑을 쓰지 않는다(무채색 `bgSelected`). 노랑 바탕 위 글자는 Ink다.
- Human Check는 노랑을 내놓고 청록(hue 195)이 된다. 상태 색은 서로, 그리고 강조색과 색상이 40° 넘게 떨어진다.
- 바탕·면은 Ink에서 밝기만 바꾼 무채색, 글자는 Paper에서 밝기만 내린 따뜻한 무채색이다. 앞 팔레트의 푸른 기(hue 260)는 뺐다.
- 0077의 브랜드 그림 색 예외(노랑은 그림 안에서만)는 강조색 규칙으로 바뀐다. 레일 맨 위 기호는 노란 취구가 있는 판을 쓴다. 마스코트를 상태 표시 곁에 두지 않는 규칙은 그대로다.

**갱신(2026-11-19, 운영자 결정, 티켓 [0100](../tickets/0100-dashboard-kanban.md)).** 운영자가 Dashboard 본문이 1200px로 고정돼 왼쪽에 붙고 넓은 창에서 오른쪽이 비는 점, To do 묶음·In progress·Runners·Done today 네 구역이 두 열에 흩어져 런이 어디쯤 있는지 한눈에 보이지 않는 점을 짚고 시안 KA·KB를 골랐다. 위 1·2·4·6·10번과 "ADR 0007과의 관계"에 반영했다. 0068 갱신의 Dashboard 항목(To do를 하는 일로 묶은 카드, 면 없는 In progress·Done today 구역)은 이것으로 바뀐다.

- **칸반 세 칸 + Runners 열.** 본문은 런 상태 기준 칸 Queued(Queued 런), Running(Running·Waiting for Input·Paused·Disconnected 런, Paused는 0118부터), Done(처음 이름은 Done today, 오늘 끝난 런. 0163 갱신으로 최근 7일)과 오른쪽 Runners 열이다. 본문 최대 폭 고정을 없앤다. 창이 넓으면(약 1440px 이상) 칸 셋 오른쪽에 Runners 열, 좁으면 Runners를 칸반 아래로 내리고, 더 좁으면(약 900px 이하) 칸을 세로로 쌓는다.
- **To do는 칸이 아니라 꼬리표.** To do 종류(Question·Permission·Human Check·Failed·Disconnected)는 카드 위 꼬리표 알약(`StatusPill`, 점 + 종류 이름)으로 보이고, 꼬리표 카드가 칸 맨 위에 온다. 무엇을 기다리는지 아직 읽지 못한 Waiting for Input 런은 꼬리표 Waiting for Input이다. To do에 오른 끝난 런은 언제 끝났어도 Done 칸에 꼬리표로 남고, 그 밖의 끝난 런은 소제목 "처리할 일 없이 끝났어요" 아래에 모은다.
- **보기.** 머리 오른쪽의 "모두 / 처리할 일만 {n}"으로 꼬리표 카드만 남길 수 있고, 주소(`?view=todo`)에 남는다.
- **상세는 오른쪽 패널.** 카드를 누르면 오른쪽에 덮여 열리는 패널(`Sheet`)이 상세를 보인다. Question은 답하기, Permission은 러너에서 허용하라는 안내와 거절, Human Check는 PR 링크, Failed는 에이전트 결과·PR 상태 두 축과 Tickets에서 다시 맡기기를 패널에서 한다. 앞선 답하기·거절하기 팝오버는 이 패널로 바뀐다. 카드를 끌어 옮기지 않는다.
- **머리의 요약 문장.** 제목("처리할 일이 {n}개 있어요")과 요약 문장은 그대로 둔다. 요약 문장은 To do 종류를 하는 일로 모아 말한다(답할 질문, 확인할 PR, 멈춘 런).
  **갱신(2026-11-19, 운영자 결정, 티켓 [0113](../tickets/0113-desktop-titlebar.md)).** 데스크톱 앱 창이 macOS 기본 제목 표시줄을 써서 어두운 앱 위에 회색 띠와 "Ganger" 제목이 따로 떴다. 운영자가 이를 이질적이라고 짚고 시안 T3을 골랐다. 위 8·11번에 반영했다.

- **한 줄 머리.** 모든 화면의 제목(화면 이름)과 요약 한 줄을 콘텐츠 맨 위 56px 한 줄에 나란히 두고, 그 아래 얇은 구분선을 둔다. 오른쪽에는 그 화면의 머리 행동(Runners의 러너 추가, Dashboard의 보기 등)을 둔다. 좁은 폭에서 요약 문장이 넘치면 말줄임하지 않고 다음 줄로 내리고, 머리 높이가 내용만큼 늘어난다. Dashboard와 Stats의 결론 문장("처리할 일은 답할 질문 2개예요", "끝난 런 40개 중 70%를 에이전트가 병합까지 끝냈어요")은 이 줄의 요약 문장이 된다. Run 상세는 티켓 제목이 제목이고, 제목 앞에 왔던 화면으로 돌아가는 `‹` 링크를 둔다(앱 안 기록이 없으면 Runs로 간다, 티켓 0181).

- **창 끌기.** 데스크톱 앱에서는 머리 줄 전체와 레일 위 56px이 창을 끄는 자리다. 그 안의 버튼·링크·입력은 끌기에서 뺀다.

**갱신(2026-11-21, 운영자 결정 R1·R5, 티켓 [0145](../tickets/0145-run-outcome-names.md)).** 요약 결과를 에이전트 보고로만 정하기로 했다(ADR [0022](0022-run-outcome-from-agent-report.md), 스펙 [0005](../spec/0005-run-outcome.md)). 위 1·5번에 반영했다.

- **요약 결과 이름.** Merged·Human Check는 Succeeded가 된다. 완료 보고(성공)는 Succeeded, 완료 보고(실패)와 그 밖의 비정상 종료는 Failed, 운영자 취소는 Canceled다. Succeeded 색은 앞선 Merged의 파랑이다.
- **To do 종류.** Human Check가 빠진다. Dashboard Done today 칸의 꼬리표는 Failed뿐이고, 머리 요약 문장의 "확인할 PR"도 빠진다. Human Check는 0148에서 에이전트가 사람 확인을 요청하는 Waiting for Input 종류로 돌아왔다. 색은 청록이고, Dashboard Running 칸 맨 위에 "확인해 주세요"로 Question과 따로 묶으며, 머리 요약 문장은 "확인할 일"로 말한다(ADR [0023](0023-human-check-request.md)).
- **PR 정보.** PR은 결과를 정하지 않고 "PR #n 열림·병합됨·닫힘·못 읽음"으로 보인다. 자세히 보는 자리는 Run 상세 PR 구역과 Runs 패널 PR 구역이다(0173·0174 갱신). Dashboard 패널의 PR 상태 줄, 끝난 런 표의 상태 칸("PR 병합됨", "CI 실패", "충돌"), Tickets 행과 마지막 런 상자에는 짧게 보인다. 이후 PR 상태가 있으면 그것을 보인다. PR 상태 없음은 보이지 않는다.
- **Stats.** 결과(Succeeded·Failed·Canceled)로 세고, 병합률 대신 성공률을 보인다. PR 병합 수는 PR 정보(끝날 때나 그 뒤 병합)에서 따로 세어 숫자 카드 하나로 보인다. 앞선 "사람이 손댄 비율" 카드는 뺀다.
- **남긴 워크트리.** Run 상세는 worker가 워크트리를 남긴 이유("PR이 없어 워크트리를 남겼어요" 등)를 처리할 일 띠(`kept-worktree`)의 문제 상자 제목으로 보이고 그 아래에 사람이 할 다음 일을 쓴다. 이 띠에는 노란 버튼이 없고, 지우기는 머리 행동의 위험 표시 "워크트리 지우기"(확인 대화상자)다. PR CI 실패·충돌이나 Failed가 먼저인 런은 그 띠 안에, 처리할 일이 없는 런은 조용한 문장에 같은 안내를 덧붙인다(0174 갱신).

이유: 제목 표시줄을 숨기면 창 맨 위 줄이 비어 신호등과 화면 제목이 따로 논다. 화면 제목과 요약을 신호등 높이의 한 줄로 모으면 그 줄이 제목 표시줄 노릇을 하면서 세로 공간도 아낀다. 제목 아래에 요약을 따로 두던 두 줄 구조와 결론 문장 제목은 이 한 줄에 들어가지 않아 요약 문장으로 바꿨다. 머리 줄 배치와 제품 기호 위치는 웹과 데스크톱이 같아야 화면 구조가 둘로 갈리지 않고, 신호등 자리만 데스크톱 앱에서 비운다. 제품 기호를 맨 위에 두면 데스크톱 앱에서 신호등과 겹쳐 맨 아래로 옮겼다.

**갱신(2026-11-19, 운영자 결정, 티켓 [0119](../tickets/0119-settings-redesign.md)).** 운영자가 Settings가 쓸데없는 정보를 다 보여 주고 온보딩과 톤이 맞지 않는다고 짚고 시안 S1(한 페이지에 모아 보기)을 골랐다. 아래 "ADR 0007과의 관계"의 Settings 항목을 바꾼다.

- **하위 화면.** 트래커 프로젝트 상세와 MCP는 주소가 있는 하위 화면이고, 머리는 "Settings ›" 링크와 이름이다.

**갱신(2026-11-19, 운영자 결정, 티켓 [0118](../tickets/0118-run-pause-resume.md)).** 운영자가 런을 끝내지 않고 잠시 멈췄다가 같은 자리에서 이어 가는 길을 원했다. 새 런 상태 Paused를 더하고 위 1·4·5번에 반영했다.

- **Paused는 회색이다.** 운영자가 스스로 멈춰 둔 런이라 사람이 답할 일(보라)도 문제(빨강)도 아니고, 진행 중(초록)도 아니다. 기존 의미 토큰 중 "대기·멈춤"인 회색 `idle`이 뜻 그대로 맞아 새 색을 만들지 않았다. 같은 회색인 Queued·Canceled와는 이름과 놓인 칸(Queued 칸, Done 칸)으로 갈린다.
- **Dashboard Running 칸에 그대로 두고 꼬리표를 단다.** Paused 런은 capacity를 계속 차지하고 끝나지 않았으므로 Running 칸에 남는다. To do가 아니지만 카드에 꼬리표 Paused를 달아(4번의 예외) 일하는 카드와 갈리게 하고, 카드에 "재개" 버튼을 둔다. Running 런 카드는 오른쪽 위 메뉴(`…`)에 "멈추기"를 둔다. To do·알림·배지에는 넣지 않는다.
- **"멈춰 둔 런".** 문장에서는 Paused 런을 "멈춰 둔 런"으로 쓴다. Dashboard 요약 문장의 "멈춘 런"은 Failed·Disconnected를 모아 부르는 말이라 섞지 않는다.
- **Runs·Tickets 필터.** Paused는 처리할 일이 아니라 진행 중에 든다. Runs 아래 줄 상태 칩에 Paused를 더한다.

**갱신(2026-11-21, 운영자 결정, 티켓 [0162](../tickets/0162-english-time-units.md)).** 1분 안의 경과가 매초 바뀌어 시선을 끌고, 하루가 넘어도 시간으로만 늘어났다. 7번의 시간 표기를 초 없는 영어 단위로 바꾼다.

- **경과·양.** 1분 안은 `<1 min`, 1시간 안은 `25 min`, 하루 안은 `1 hr 3 min`(분이 0이면 `2 hr`), 하루 이상은 `1 day`·`2 days`이고 시간·분은 버린다. "째"는 쓰지 않는다.
- **지난 일.** `Just now`, `25 min ago`, `3 hr ago`이고 하루가 넘으면 지금처럼 날짜다.
- **바꾸지 않는 것.** 시각, 날짜, 통계 날짜, 사용량 창 이름("5시간", "주간")은 그대로다.

**갱신(2026-11-21, 운영자 결정, 티켓 [0163](../tickets/0163-dashboard-done-week.md)).** Done today 칸은 오늘 끝난 런만 보여서 아침이면 어제 끝난 일이 바로 사라졌다. 칸 이름을 Done으로 바꾸고 최근 7일 동안 끝난 런까지 보인다. 위 2·4·10번과 0100 갱신, "ADR 0007과의 관계"에 반영했다. 앞선 갱신의 기록 문장에 남은 Done today는 그때의 이름이다.

- **7일.** 운영자 시간대로 오늘을 포함한 7개 날짜(오늘과 앞선 6일)다. 그보다 앞서 끝난 런은 칸에 넣지 않는다.
- **To do 꼬리표.** Failed 꼬리표 런은 날짜와 상관없이 칸 맨 위에 남는다. 칸 머리 개수는 칸에 든 카드 전체라, 꼬리표 카드(날짜 무관)와 최근 7일의 "처리할 일 없이 끝났어요" 카드를 더한 수다. "처리할 일만" 보기의 개수는 꼬리표 카드 수다.
- **그대로 두는 것.** 보이는 카드 수 제한과 "Runs에서 모두 보기" 링크(기간 필터 없음)는 그대로다. MCP `get_dashboard`의 `doneToday`는 칸과 따로 오늘 끝난 런을 뜻한다.

**갱신(2026-11-22, 운영자 결정, 티켓 [0174](../tickets/0174-run-detail-page.md)).** Runs 패널과 Run 상세가 같은 런의 처리할 일을 다르게 말했고, PR 정보가 여러 곳에 흩어졌으며, 런 정보 카드가 터미널을 아래로 밀었다. Run 상세를 아래 구조로 바꾸고 "ADR 0007과의 관계"와 0145 갱신의 PR 정보·남긴 워크트리에 반영했다.

- **처리할 일 띠.** 공용 함수 `runNextStep`이 Runs 패널과 같은 판단으로 맨 위 띠의 문장을 정한다. 처리할 일이 없으면 띠 없이 조용한 문장만 둔다. 띠의 노란 주 버튼은 실패한 검사 보기, PR에서 충돌 보기, 재개하기에만 쓴다.
- **왼쪽 칸.** 기다리는 일(선행 티켓 대기, 입력 대기, 마지막 출력, 시작 오류), PR 구역, 지나온 일, 에이전트에게 보내기 순서다.
- **오른쪽 칸.** 런 정보(러너, 에이전트·모델, 대기·실행, 있으면 워크트리)와 그 안에 접은 받은 지시서, 터미널 끝부분, 같은 티켓의 다른 런 순서다.
- **머리.** 이어서 맡기기, 멈추기, 런 취소, 워크트리 지우기는 보조·위험 버튼으로 머리 오른쪽에 둔다. 재개는 띠의 주 버튼이다.

## 이유

- **일관성.** 같은 상태가 화면마다 다른 이름·모양·색이면 운영자는 같은 것인지 매번 확인해야 한다. 상태 알약, 시간 표기, 제목 규칙을 하나로 두면 화면을 옮겨도 읽는 법이 같다.
- **상태 이름을 GLOSSARY와 하나로.** 화면에서만 한국어로 바꾸면("실행 중", "입력 기다림", "연결 끊김", "취소") 코드·문서·화면의 이름이 둘이 되고, Human Check처럼 영어로 남은 이름과 섞인다. 상태 이름은 GLOSSARY 용어가 곧 화면 낱말이 되게 한다. 설명 문장은 읽히는 것이 목적이라 한국어로 둔다.
- **색 의미 겹침 해소.** 지금은 상태 대부분이 무채색이라 Running과 Queued, Waiting for Input과 Queued가 모양으로 구별되지 않고, 주황(Human Check)과 빨강(Failed)이 가까워 둘을 헷갈린다. 사람이 해야 할 일의 종류(답·허용, 확인, 문제 해결)마다 색을 하나씩 주면 To do에서 무엇을 할지 색으로 먼저 안다. Human Check는 처음에 노랑으로 갈랐고, 0080에서 노랑이 브랜드 강조색이 되면서 청록(hue 195)으로 옮겼다. 청록은 빨강(Failed)과 멀고, 초록(Running, hue 150)·파랑(Merged, hue 245)과는 색상이 45°·50° 떨어지고 밝기도 더 밝아 갈린다. 주황은 Failed와 헷갈린 기록이 있어 쓰지 않았다.

## ADR 0007과의 관계

이 ADR은 [ADR 0007](0007-ui-list-detail-panel.md)을 **보완하고 일부를 대체한다.**

- **남는 것.** 목록 + 오른쪽 상세 패널은 Tickets에 남고, 0068 갱신으로 Runners도 이 구조로 돌아온다. Runs는 0173 갱신으로 이 구조를 떠나 러너 카드·기다리는 런 카드·끝난 런 표가 되었고, 런을 한 번 누르면 오른쪽에 덮여 열리는 `Sheet`가 요약을 보이며 그 안의 링크로 Run 상세로 간다. Stats는 처음에 지금 구조(목록 + 패널)를 그대로 두었지만, 0068 갱신으로 오른쪽 패널을 없앴다. Tickets는 행을 고르면 패널에 요약이 보이고, 행의 버튼이나 패널의 런 목록으로 Run 상세로 간다. Settings의 이 Workspace·설치 전체 나누기는 저장 규칙으로 남고, 화면은 0119 갱신으로 한 페이지가 되어 목록 + 패널을 쓰지 않는다.
- **바뀌는 화면.** Dashboard는 목록 + 패널 대신 런 상태 칸반 세 칸(Queued·Running·Done)과 오른쪽 Runners 열이고, 카드를 누르면 오른쪽에 덮여 열리는 패널이 상세를 보인다(0100 갱신). Run 상세는 패널이 아니라 전체 화면으로 열고, 맨 위에 처리할 일 띠, 그 아래 왼쪽 칸에 기다리는 일·PR 구역·지나온 일·에이전트에게 보내기, 오른쪽 칸에 런 정보·터미널 끝부분·다른 런을 둔다(0174 갱신). Runners는 처음에 러너 카드(capacity 막대, 해결 안내)로 바꿨지만, 0068 갱신으로 목록 + 상세 패널로 돌아왔다. Stats는 패널 없이 결론 제목, 숫자 넷, 날짜별 차트, 실패 이유, 나눠 보기를 한 열로 둔다. 온보딩은 가운데 한 열이 아니라 왼쪽 단계 목록·가운데 입력·확인 결과로 나눈다(사이드바 없는 첫 진입 전용 화면, 모든 단계 필수, 확인이 성공해야 다음으로 가는 점은 그대로).
- **대체하는 규칙.** 0007의 "색은 손댈 일에만 쓴다"(Human Check 주황), "카드와 배지를 쓰지 않는다", "구역은 옅은 선과 여백으로 나눈다"는 이 ADR의 5·10번과 카드(Dashboard To do 등)가 대신한다. 행 안의 위계(제목이 가장 밝고 굵고 ID·러너·시간은 흐리게, 숫자는 tabular-nums)는 그대로다.

대체가 아닌 보완으로 둔 까닭: 훑고 고르는 화면(Tickets·Runners)에서는 페이지를 옮기지 않는 목록 + 패널이 여전히 맞고, 바뀌는 것은 "할 일을 먼저 보여 줄 화면"(Dashboard), "러너별로 지금을 볼 화면"(Runs, 0173 갱신)과 "한 런을 깊게 볼 화면"(Run 상세)이다.

## Consequences

- **Done 칸은 DB에 이미 있는 런 끝 기록만으로 보인다.** 처음 정한 "지금 일어나는 일" 흐름(런 상태 바뀜, 질문, 권한 대기, 런 끝·PR 기록)은 위 갱신에서 뺐다. 런 중간 진행(시안의 "커밋 n개")은 러너에서 받아 오는 데이터가 없어 넣지 않았고, 넣으려면 러너 어댑터가 무엇을 얼마나 자주 읽을지 따로 정해야 한다.
- **`packages/ui`의 규칙 문서(`DESIGN.md`)와 토큰 시험이 바뀐다.** 지금 문서는 "카드와 배지를 쓰지 않는다", "색은 손댈 일에만", 반경 `md 6`을 적고, `tokens.test.ts`는 채도 있는 색을 포인트·Human Check·Failed·Online에만 허락한다. 적용 티켓([0049](../tickets/0049-ui-redesign.md))이 토큰·컴포넌트와 함께 고친다. 그 전까지 이 ADR과 `DESIGN.md`가 다르면 이 ADR이 앞선다.
- **파랑은 Succeeded 하나에만 쓴다.** 처음에는 포인트 파랑이 Merged 알약과 주 버튼·링크 둘에 쓰였다. 0080에서 강조색이 노랑이 되어 주 버튼·링크는 노랑이고, 파랑은 Merged 상태 색으로만 남았다. 0145에서 요약 결과 Merged가 Succeeded가 되어 파랑은 Succeeded 색이다. Stats 차트의 Succeeded 막대도 파랑이다.
- **이 ADR이 앞선 문서의 화면 낱말보다 앞선다.** [1단계 스펙](../spec/0001-phase-1.md)(Disconnected를 "연결 끊김", Canceled를 "취소"로 쓴다는 문장)과 `design/prototype/README.md`(Running을 "실행 중"으로 쓴다는 문장), 끝난 티켓들의 같은 문구는 그때의 기록이다. 상태 이름의 화면 낱말은 이 ADR과 GLOSSARY를 따른다.
- **메시지 파일 낱말을 바꾼다.** "실행 중", "입력 기다림", "연결 끊김", "취소", "인증 깨짐", "권한 대기", "홈" 같은 상태·화면 이름을 영어 용어로 바꾸고, 시간 표기는 함수 하나로 모은다. 적용은 0049에서 한다.

- **Tickets는 상위 이슈로 묶어 보인다(2026-11-22 갱신, 운영자 결정, [티켓 0171](../tickets/0171-tickets-parent-grouping.md)).** Tickets가 Runs와 너무 비슷하다는 지적에 따라 기본 보기를 상위 이슈 묶음으로 바꾸고, 티켓 하나씩 보는 보기를 아이콘 버튼으로 함께 둔다. 모든 줄은 [상태 아이콘][키][제목][런][할 일] 다섯 칸이다. Linear 상태는 런 칸에 쓰지 않고 분류별 아이콘 모양으로 보이며, 색은 Ganger 중립색으로 고정한다. 런 상태는 런 칸에 점과 이름으로 보이고, Tickets 목록에서는 상태 알약·우선순위·트래커 프로젝트 칸을 뺀다.
- **Runs 목록은 한국어 한 마디로 말한다(2026-11-22 갱신, 운영자 결정, [티켓 0173](../tickets/0173-runs-by-runner.md)).** Runs가 복잡하고 상태가 많아 한눈에 파악하기 어렵다는 지적에 따라 러너 기준의 "지금" 카드와 "끝난 런" 표로 바꾼다. 목록과 상황 문장의 상태는 한국어 한 마디(도는 중, 답을 기다려요, 허용을 기다려요, 확인을 기다려요, 답을 보냈어요, 거절했어요, 취소 중, 멈춰 있어요, 러너와 끊겼어요, 끝남, 확인 필요, 실패, 취소됨)로 쓴다. Queued 런은 "기다리는 런" 카드에 줄마다 짧은 이유(자리를 기다려요, 선행 티켓을 기다려요, 러너가 꺼져 있어요, 사용 한도에 닿았어요 등)로 쓴다([티켓 0178](../tickets/0178-runs-polish.md)). 1번의 영어 상태 이름과 4번의 상태 알약은 패널과 런 상세에 남는다. 패널은 ADR 0007의 고정 패널 대신 Dashboard처럼 오른쪽에 덮여 열리는 `Sheet`다.

## Considered Options

- **상태 이름도 모두 한국어로**: 화면은 한 언어가 되지만 GLOSSARY·코드의 영어 용어와 이름이 둘이 되고, Human Check·Merged처럼 마땅한 한국어가 없는 이름에서 다시 섞인다. 기각했다.
- **ADR 0007을 통째로 대체**: Runs·Tickets의 목록 + 패널은 운영자가 바꾸자고 하지 않았고 여전히 맞는다. 바뀐 화면과 규칙만 대체했다(이 판단은 그때의 기록이고, Runs는 뒤에 0173 갱신으로 바뀌었다).
- **색을 손댈 일에만 두는 지금 규칙 유지**: 상태끼리 모양이 같아 구별되지 않는다는 점검 결과가 이 ADR의 출발이라 기각했다.
