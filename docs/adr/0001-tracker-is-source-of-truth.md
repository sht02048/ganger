# 트래커가 티켓의 기준이다

티켓의 상태와 내용은 트래커(1단계는 Linear)가 기준이고, 오케스트레이터는 런과 통계용 이력만 저장한다. 오케스트레이터가 티켓을 복제해 따로 관리하면 두 곳의 상태가 어긋나기 때문이다. 오케스트레이터가 트래커를 갱신하는 때는 둘뿐이다. 런이 시작하면 티켓 상태를 "In Progress"로 바꾸고, 런이 끝나면 결과 댓글을 단다. 그 뒤 PR에 따른 상태(In Review, Done)는 Linear의 GitHub 연동에 맡긴다. 할당은 Linear webhook으로 감지하고, 놓친 이벤트는 주기적 폴링으로 맞춘다.

**갱신(2026-11-22, 운영자 결정, [티켓 0170](../tickets/0170-merged-ticket-state.md)):** Linear의 GitHub 연동이 없는 환경도 있어, 트래커를 갱신하는 때에 선택 설정 하나를 더한다. 트래커 프로젝트 설정에서 "PR이 머지되면 바꿀 상태"를 고르면 worker가 런의 PR 머지를 확인할 때 티켓을 그 상태로 런마다 한 번 바꾼다. 처음 값은 "바꾸지 않음"이고, 그때는 PR에 따른 상태를 지금처럼 Linear의 GitHub 연동에 맡긴다.
