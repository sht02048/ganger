# GitHub 인증은 서버 기계의 gh 로그인을 먼저 쓰고 붙여 넣은 토큰은 대체 수단으로 둔다

Ganger 서버는 PR을 읽고(0200) 머지할 때(0201, [ADR 0024](0024-operator-merges-pr-from-ganger.md)) Settings·온보딩에 붙여 넣은 GitHub 토큰 하나를 썼다. 운영자는 토큰을 따로 만들어야 했고, 회사·개인 계정처럼 저장소 주인이 다른 계정을 함께 쓰면 토큰 하나로는 모든 저장소를 볼 수 없었다. 같은 기계의 Orca는 GitHub CLI 로그인을 `gh auth token --user <계정>`으로 빌려 쓴다. 2026-11-23 운영자가 Ganger도 gh 로그인을 기본으로 쓰기로 정했다(티켓 [0204](../tickets/0204-github-auth-via-gh.md)).

## 결정

1. **서버 기계의 gh 로그인을 먼저 쓴다.** 서버 프로세스를 돌리는 사용자의 `gh` 로그인이다. 서비스로 돌거나 원격 기계에서 돌면 그 기계·그 사용자의 로그인만 쓴다. Ganger가 다른 기계의 gh를 빌리지 않는다.
2. **저장소마다 그 저장소를 볼 수 있는 gh 계정을 자동으로 고른다.** 활성 계정부터 차례로 `GET /repos/{owner}/{repo}`가 되는 계정을 고르고, 고른 결과를 10분 캐시한다. 그 계정으로 부른 요청이 `unauthorized`·`not-found`로 실패하면 고른 결과를 잊고 다음 호출에서 다시 고른다. 저장소별로 계정을 손으로 묶는 설정은 두지 않는다.
3. **붙여 넣은 토큰으로 넘어가는 것은 세 경우뿐이다.** gh가 없거나, gh에 로그인한 계정이 없거나, 어느 gh 계정도 그 저장소를 볼 수 없을 때다. 볼 수 있는 계정도 토큰도 없으면 활성 계정을 그대로 써서 지금처럼 "PR을 읽을 수 없다"가 드러나게 한다.
4. **고른 출처의 권한이 모자라도 다른 출처로 넘어가지 않는다.** gh 계정이 저장소를 보지만 머지 권한이 없으면 ADR 0024 4번처럼 버튼을 끈다. 요청마다 출처가 바뀌면 운영자가 어느 계정으로 머지됐는지 알기 어렵다.
5. **gh는 공식 명령만 고정 인자로 부르고 출력은 경계에서 파싱한다.** `gh --version`, `gh auth status --hostname github.com [--json hosts]`, `gh auth token --hostname github.com [--user <계정>]`이다. 계정 이름은 GitHub 로그인 꼴만 넘긴다. gh 2.40보다 낮으면 `--user`가 없어 활성 계정 하나만 쓰고 화면에 그 사실을 적는다. gh 위치는 `GANGER_GH_CLI`, `PATH`, 알려진 자리 순서로 찾는다.
6. **토큰 값은 밖으로 내보내지 않는다.** gh에서 받은 토큰은 메모리에만 5분 두고 DB에 저장하지 않는다. 화면 상태(`GitHubAuthView`)와 MCP 응답은 계정 이름과 볼 수 있는 곳(계정·조직 이름)만 담는다.
7. **gh로 연결하면 토큰 없는 코드 호스트 연결을 저장한다.** Settings·온보딩의 "다시 확인"(MCP `check_github_token`)이 gh 로그인으로 GitHub에 닿으면 `secrets`가 빈 연결을 저장한다. worker와 머지가 지금처럼 저장한 연결을 따라 코드 호스트를 만들고, 온보딩 완료 판단도 그대로 연결이 있는지를 본다. 토큰을 붙여 넣으면 그 토큰만으로 확인한 뒤 같은 연결에 저장한다.

## 되돌리기 어려운 이유

운영자가 토큰 없이 gh 로그인만으로 Ganger를 설치하면, 이 순서를 바꿀 때 그 설치들이 PR을 읽지 못하게 된다. 토큰 없는 코드 호스트 연결이 DB에 남는 것도 이 결정에 기댄다. 또 붙여 넣은 토큰이 있는 설치에서도 gh 로그인이 있으면 PR을 읽는 계정이 바뀐다.

## 고려한 대안

- **붙여 넣은 토큰을 먼저 쓰고 gh를 대체로.** 지금 설치는 그대로지만 토큰을 만들지 않으면 gh가 쓰이지 않고, 계정이 여럿인 문제를 풀지 못한다.
- **저장소마다 계정을 고르는 설정.** 정확하지만 저장소가 늘 때마다 손이 간다. 자동 고르기로 대부분 풀리고, 못 고르면 활성 계정이나 토큰으로 드러난다.
- **권한이 모자라면 토큰으로 다시 시도.** 머지가 될 때가 늘지만 어느 계정이 머지했는지 흐려지고 실패 이유도 섞인다.
- **gh 토큰을 DB에 저장.** worker와 web이 같은 값을 쓰지만 비밀값이 하나 더 저장되고 gh 쪽 로그아웃·교체를 따라가지 못한다.

## 결과

- `packages/codehost-github`에 `GitHubAuth`가 생기고 `GitHubCodeHost`는 호출마다 저장소에 맞는 자격을 받는다. 확인용으로 `config.credentials = "token"`을 주면 붙여 넣은 토큰만 쓴다.
- 설치 설정에 `githubConnected`(코드 호스트 연결 있음)가 생기고 `githubToken`은 붙여 넣은 토큰이 있는지를 뜻한다.
- ADR 0024 4번의 "토큰을 어디서 얻는지가 바뀌어도 머지 코드는 그대로다"를 이 ADR이 채운다.
