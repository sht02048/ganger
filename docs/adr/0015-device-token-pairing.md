# 다른 기기 클라이언트는 기기 토큰으로 인증하고 QR로 연결한다

지금 서버에는 로그인이 없다. Host·Origin 허용 목록(`packages/app/src/request-guard.ts`)은 브라우저를 지키는 장치이지 접근 제어가 아니고, 서버 주소에 닿는 기기(Tailscale을 쓰면 tailnet의 기기)는 누구나 쓰기를 할 수 있다(research [0014](../research/0014-mobile-client.md) 1절). ADR [0013](0013-mcp-client-scope.md)은 다른 기기 클라이언트를 "서버 인증이 생긴 뒤 다시 정한다"고 미뤘다. 모바일 앱(스펙 [0002](../spec/0002-mobile.md))은 폰을 잃어버릴 수 있는 기기에서 런에 답하고 취소한다. 그래서 기기마다 따로 끊을 수 있는 인증이 먼저 필요하다(2026-11-19 운영자 결정 M2).

## 결정

- **기기마다 토큰 하나.** 서버가 연결한 기기마다 무작위 토큰을 내준다. 서버는 토큰의 해시만 저장하고 토큰 자체는 두지 않는다. 기기는 요청마다 `Authorization: Bearer <토큰>`을 보낸다.
- **QR로 연결한다.** 서버 쪽 Ganger 화면이 기기 연결 QR을 띄운다. QR에는 서버의 "다른 기기에서 열 주소"(GLOSSARY, Settings에서 정한다)와 짧게 살고 한 번만 쓰는 연결 코드가 들어 있다. 앱이 QR을 읽어 연결 코드와 기기 이름을 보내면 서버가 토큰을 내준다. 연결 코드도 해시만 두고, 티켓 0097의 러너 등록 토큰처럼 서버 메모리에만 둔다(서버를 다시 켜면 사라진다). 기기 토큰의 해시는 DB에 둔다.
- **기기 목록에서 끊는다.** 연결한 기기의 이름, 연결한 때, 마지막 접속을 보이고, 지우면 그 토큰이 바로 거절되고, 그 토큰으로 이미 열린 연결(SSE 등)도 닫힌다. 기기는 자기 연결을 스스로 끊을 수도 있다.
- **토큰은 `/api/v1`에만 요구한다.** 웹 화면, 서버 함수, `/api/identity`, webhook은 바꾸지 않는다. 연결 코드를 토큰으로 바꾸는 경로만 토큰 대신 연결 코드로 인증한다.
- **iOS 앱에 ATS 예외를 두지 않는다.** 그래서 서버는 HTTPS 주소로 닿아야 한다. 예외는 개발 빌드 하나로, 시뮬레이터가 `127.0.0.1`의 평문 http dev 서버에 붙도록 `NSAllowsLocalNetworking`만 둔다. 출시 빌드에는 두지 않는다(스펙 0002 M46).

## 고려한 대안

- **Tailscale 신원 헤더에 기댄다.** Tailscale Serve를 거칠 때만 붙는 헤더라 Serve 없이 붙는 설치에서는 쓸 수 없다. ADR [0005](0005-self-hosted-product.md)는 Tailscale을 권장 구성으로만 둔다. 기기를 따로 끊을 수도 없다.
- **인증 없이 네트워크를 믿는다.** 폰을 잃어버리면 그 폰을 서버 주소에 닿는 네트워크(Tailscale을 쓰면 tailnet)에서 빼기 전까지 런에 답하고 취소할 수 있다.
- **아이디·비밀번호 로그인.** 설치 하나에 운영자가 한 명(ADR 0005)이라 계정 관리가 짐만 된다. 기기를 따로 끊는 일은 결국 기기 토큰이 필요하다.

## 결과

- one-way다. 기기 표를 더하는 DB 마이그레이션과, 앱이 기대는 공개 계약(`/api/v1`의 인증 방식)이 생긴다.
- 웹 화면은 여전히 인증이 없다. 그래서 잃어버린 기기를 목록에서 지워도, 그 기기를 서버 주소에 닿는 네트워크(Tailscale을 쓰면 tailnet, 리버스 프록시나 터널이면 그 주소에 닿는 모든 곳)에서 빼기 전까지는 브라우저로 웹 화면을 열어 답하고 취소할 수 있고, 웹의 기기 연결 화면에서 새 토큰을 받을 수도 있다. 이 결정만으로 잃어버린 기기를 완전히 막지는 못한다. 웹 인증은 모바일 범위 밖으로 두고 지금처럼 네트워크 경계와 Host 검사에 맡긴다(스펙 0002 M36).
- 알림 사건 SSE도 `/api/v1` 아래에 두므로(스펙 0002 M6) 데스크톱 앱도 이 인증을 거쳐야 한다. 데스크톱도 기기 토큰을 쓰고 같은 기계·원격 모두 첫 연결 때 자동 등록한다(스펙 0002 M39).
- 서버에 HTTPS 주소가 필요하다(ATS 예외를 두지 않으므로, research 0014 3절). `request-guard`는 Host가 loopback, 바인드 주소, "다른 기기에서 열 주소"일 때만 요청을 받는다. QR에는 "다른 기기에서 열 주소"만 쓰므로, 그 주소가 비었거나 https가 아니면 기기 연결 QR을 띄우지 않고 Settings의 주소 칸으로 안내한다. 티켓 0230부터 주소 칸은 없고, Settings › 모바일에서 Tailscale Serve를 켜면 그 https 주소가 들어간다.
- 토큰은 만료하지 않고 지우기로 끊으며, 기기 목록은 웹 Settings에 둔다(데스크톱도 그 화면, 스펙 0002 M35).
- 같은 인증을 나중에 HTTP MCP 같은 다른 기기 클라이언트에도 쓸 수 있다(ADR 0013을 다시 정할 때).

## 갱신(2026-11-23)

운영자 결정 M25~M27, M35, M36, M39(스펙 0002 11절, 티켓 [0188](../tickets/0188-mobile-plan-refresh.md))로 v1 계약에 다음을 더한다. 기기마다 토큰을 두고 해시만 저장하는 방식은 바뀌지 않는다.

- 변경 기록 SSE(ADR [0019](0019-query-cache-and-change-events.md))도 v1 아래에 이 기기 토큰 인증으로 연다. 위 「기기 목록에서 끊는다」대로 기기를 지우면 이 연결도 닫힌다. 웹의 `/api/change-events/stream`은 그대로 둔다.
- v1의 모든 쓰기는 `requestId`가 필수이고, v1 응답에는 서버 버전과 계약 버전을 싣는다.
- `request-guard`의 Host 거절(403)은 토큰 거절과 다른 응답이다. 403 본문에는 이유 값이 없어, 앱은 `/api/identity`의 `webAccess`로 둘을 갈라 안내한다(티켓 [0157](../tickets/0157-address-webhook-setup.md)).
- 데스크톱의 첫 연결 자동 등록은 위 「토큰은 `/api/v1`에만 요구한다」의 예외(연결 코드 교환)에 더하는 두 번째 예외다. 연결 코드 없이 토큰을 내주므로 서버 주소에 닿는 기기는 토큰을 얻을 수 있다. 자동 등록은 저장한 기기 토큰이 없을 때만 하고, 토큰이 거절되면(지운 뒤) 조용히 다시 등록하지 않고 사용자가 "다시 연결"을 눌러야 다시 등록한다(스펙 0002 M48).
- 개발 빌드의 로컬 자동 연결(M45)은 위 「iOS 앱에 ATS 예외를 두지 않는다」의 개발 빌드 예외(M46)로 붙는다. 제품 빌드의 규칙은 그대로다.
