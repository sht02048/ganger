# 화면 구조는 목록 + 오른쪽 상세 패널이다

운영 화면은 목록과 오른쪽 상세 패널로 나눈다. 목록에서 행을 고르면 패널에 그 항목의 상태, 이유, 러너, 에이전트, 경과 시간, PR·CI, 다음 행동이 바로 보여, 페이지를 옮기지 않고 훑고 판단할 수 있다. 홈, Tickets, Runs, Runners, Stats가 같은 구조를 쓰고, Settings도 왼쪽 항목 목록과 오른쪽 편집 영역으로 같은 규칙을 따른다.

- **행은 정렬된 열이다.** 제목이 가장 밝고 굵고, 티켓 ID·러너·시간은 흐리게 둔다. 숫자는 tabular-nums, 열 머리글은 작고 흐리게 둔다. 손댈 일 행만 제목 아래 이유 한 줄을 더한다.
- **색은 손댈 일에만 쓴다.** Human Check는 주황, Failed는 빨강이고 나머지는 무채색과 포인트 색 하나다. 러너 Online·Offline 점만 예외로 PR #3 사이드바의 초록·빨강을 따른다.
- **카드와 배지를 쓰지 않는다.** 구역은 옅은 선과 여백으로 나눈다.
- **Settings는 이 Workspace와 설치 전체로 나눈다.** 이름·트래커 프로젝트·Mapping·Auto-assign Label은 현재 Workspace, 트래커 연결·GitHub 토큰·러너 등록은 설치 전체다(ADR 0006).
- **온보딩은 첫 진입 전용 전체 화면이다.** 사이드바 없이 가운데 한 열에 한 단계씩 두고, 모든 단계가 필수이며 확인이 성공해야 다음으로 간다.

**갱신(2026-11-18, 운영자 결정, [ADR 0010](0010-ui-words-and-visual-rules.md)).** 목록 + 상세 패널은 Runs·Tickets에 남는다. Dashboard(지금은 Queued·Running·Done 칸과 Runners 열, 처음 이름은 Home), Run 상세(전체 화면), 온보딩(왼쪽 단계·가운데 입력)은 0010을 따르고, 위의 "색은 손댈 일에만", "카드와 배지를 쓰지 않는다", 옅은 선으로 구역 나누기는 0010의 색·둥글기·면 규칙이 대신한다. 0010의 0068 갱신(2026-11-18)으로 Runners는 러너 카드에서 다시 목록 + 상세 패널로 돌아왔고, Stats는 오른쪽 패널을 없앴다.

**갱신(2026-11-19, 운영자 결정, 티켓 [0119](../tickets/0119-settings-redesign.md)).** Settings는 목록 + 오른쪽 편집 영역을 쓰지 않고 한 페이지에 모아 본다(시안 S1). 왼쪽은 고르는 목록이 아니라 구역 목차(Workspace · 프로젝트 · 연결 · 이 서버 · 고급)이고, 본문 한 열에 구역마다 카드 하나와 줄(라벨 · 값 · 동작 하나)을 쌓는다. 위의 "Settings는 이 Workspace와 설치 전체로 나눈다"는 범위 표시를 화면에서 뺐다(Workspace 구역만 이 Workspace의 값이고 나머지는 설치 전체라는 나눔은 저장 규칙으로 그대로다, ADR 0006). 이유: 설정은 훑고 고를 항목이 열 개 남짓이라 행을 골라 패널을 바꾸는 이점이 없고, 오른쪽 편집 영역은 한 번에 한 항목만 보여 어디에 무엇이 있는지 찾기 어려웠다. 항목마다의 요약 칸·범위 표시·늘 보이는 안내 문단이 같은 정보를 되풀이했다(운영자 보고: "너무 쓸데없는 정보 다 보여주고 온보딩이랑 톤도 안 맞고"). 트래커 프로젝트 하나의 설정처럼 깊은 것은 주소가 있는 하위 화면(프로젝트 상세, MCP)으로 연다. Runs·Tickets·Runners는 목록 + 상세 패널 그대로다. 러너 등록·수정은 Settings에서 빼고 Runners 상세 패널이 맡는다.

**갱신(2026-11-22, 운영자 결정, 티켓 [0173](../tickets/0173-runs-by-runner.md)).** Runs는 목록 + 상세 패널을 쓰지 않는다. 러너 카드, 기다리는 런 카드, 끝난 런 표로 나누고, 런을 한 번 누르면 Dashboard처럼 오른쪽에 덮여 열리는 `Sheet`가 상세를 보인다. 목록 + 상세 패널은 Tickets·Runners에 남는다. 위 갱신의 "Runs·Tickets"는 그때의 기록이다.

## Considered Options

- **구조를 매번 새로 짠 홈 3안**: 안마다 구역 배치가 달라 위계가 정돈되지 않았다.
- **카드 칸반에 톤만 바꾼 3안**: 칸반 틀이 같아 본문이 나아지지 않았다.
- **공장 관제·비행 스트립 규칙으로 화면을 만드는 손잡이 생성기**: 정보가 지나치게 많아 무엇을 먼저 볼지 알 수 없었다.
- **탭 하나(A)**: 위계는 분명했지만 정보가 너무 축약됐다.
- **라이트 섹션형(C)**: 세로로 길어지고 화면끼리 구분이 약했다.
