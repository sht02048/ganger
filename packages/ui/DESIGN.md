# 디자인 시스템 규칙

`packages/ui`의 토큰과 컴포넌트를 쓰는 규칙이다. 화면을 만들거나 고치는 사람과 에이전트는 이 문서를 따른다. 값의 출처는 운영자가 고른 시안 B(`design/prototype/`)와 [ADR 0010](../../docs/adr/0010-ui-words-and-visual-rules.md)(낱말과 시각 규칙)이고, 화면 구조 결정은 ADR 0007·0010, 스택은 ADR 0003에 있다. 이 문서와 ADR 0010이 다르면 ADR 0010이 앞선다. 실제 모양은 `apps/web`의 `/ds`에서 본다.

## 꼭 지킬 것

1. **색 값을 직접 쓰지 않는다.** `packages/ui` 밖에서 hex, `rgb()`, `hsl()`, `oklch()`, `color-mix()`, `"red"` 같은 이름 색을 쓰면 `pnpm check:colors`(pre-commit, CI)가 실패한다. 색은 `@ganger/ui/tokens.stylex`의 `colors`로만 쓴다. `transparent`, `currentColor`, `inherit`는 괜찮다.
2. **UI SDK(`@ui-sdk/react`)는 `packages/ui` 안에서만 import 한다.** 앱은 `@ganger/ui`의 컴포넌트를 쓴다. 필요한 동작이 없으면 `packages/ui`에 컴포넌트를 더한다(ADR 0003).
3. **스타일은 StyleX로 쓴다.** `stylex.create` + `stylex.props`. 간격·글자·반경·모션도 토큰을 먼저 쓴다. 토큰에 없는 값(열 폭, 고정 높이)만 숫자로 쓴다.
4. **화면 문구는 컴포넌트에 쓰지 않는다.** 모든 글은 `apps/web/messages/ko/*.json`에 두고 `useTranslations`로 가져온다. 접근 가능한 이름(`label`, `aria-label`)도 메시지에서 온다. `packages/ui` 컴포넌트는 문구를 props로만 받는다(ADR 0005).
5. **색 하나에 뜻 하나다(ADR 0010 5번).** 상태 색은 여섯 뜻뿐이다: 보라 `answer`(사람이 답·허용), 청록 `check`(사람이 확인, Human Check), 빨강 `problem`(문제), 초록 `progress`(진행·정상), 파랑 `merged`(Succeeded), 회색 `idle`(대기·멈춤). 상태 색은 화면이 고르지 않고 `StatusPill`이 상태 값으로 고른다. 그 밖의 강조는 브랜드 노랑 Ganger Yellow(`accent*`) 하나다. 로고 취구·마스코트 모자도 같은 `accent`를 쓴다(티켓 0080).
6. **상태는 `StatusPill` 하나로만 보인다(ADR 0010 4번).** 점 + GLOSSARY 영어 이름. 예외는 Dashboard다(ADR 0010 0100 갱신). 칸반 카드(`KanbanCard`)는 To do인 카드와 Paused 런 카드(티켓 0118)에만 꼬리표 알약(`tag`)을 달고, 나머지 카드는 칸 이름이 상태를 대신하거나 상태 이름을 글로 쓴다. 면 없는 Runners 열의 행은 알약 대신 상태 점(`StatusDot`) 하나로 상태를 보인다. Tickets 목록(`IssueRow`, 티켓 0171)도 런 칸에 알약 대신 점과 이름을 쓴다. 영역은 선이 아니라 면으로 나누고, 면은 아래 면 역할로 고른다.
7. **변형을 새로 만들지 않는다.** 아래 표에 없는 변형이 필요하면 먼저 이 문서와 컴포넌트에 더하고, `/ds`에 미리보기를 넣는다.
8. **화면은 역할과 컴포넌트만 쓰고 토큰을 직접 쓰지 않는다.** 글자는 `Text` 변형이나 `textStyles(역할)`, 면은 `Card surface`나 `surfaceStyles(역할)`, 구역 제목은 `Section titleRole`로 고른다. `apps/web`에서 `colors`·`fontSize`·`fontWeight`·`lineHeight`·`letterSpacing`·`radius`·`shadow`·`motion`을 가져오면 lint(`no-restricted-imports`)가 실패한다. 배치에 필요한 `space`·`size`·`breakpoints`만 직접 쓴다(티켓 0074).
9. **HTML 요소를 직접 쓰지 않는다.** `apps/web`에서 `button`, `input`, `select`, `textarea`, `table`, `h1`~`h3`을 쓰면 lint(`react/forbid-elements`)가 실패한다. `Button`, `Input`, `Textarea`, `RadioOption`, `Select`, `DataTable`·`Table`, `Text`(`as="h2"` 등)를 쓴다. 공용 컴포넌트에 없는 속성이 필요하면 `packages/ui`를 넓힌다.
10. **길이 값을 직접 쓰지 않는다.** `apps/web` 스타일에서 여백·간격·둥글기·폭·위치에 px 숫자(단위 없는 숫자 포함)나 rem·em 숫자를 쓰면 `pnpm check:lengths`(pre-commit, CI)가 실패한다. 여백은 `space`, 폭·높이는 뜻에 맞는 `size` 토큰, 미디어·컨테이너 쿼리는 `breakpoints`로 쓴다. 값이 우연히 같다고 다른 뜻의 토큰을 빌려 쓰지 않는다. 없으면 뜻을 이름에 담은 토큰을 더한다.

`/ds`(`apps/web/src/ds/`)는 토큰 자체를 보여 주는 곳이라 토큰 import와 길이 값 검사에서 뺀다. HTML 요소 검사는 받는다. 시험 파일(`*.test.ts(x)`)은 HTML 요소 검사와 길이 값 검사에서 뺀다. 토큰 import 검사는 시험 파일에도 걸린다.

## 토큰

`import { colors, space, … } from "@ganger/ui/tokens.stylex"`. 모두 `stylex.defineVars`로 만든 CSS 변수다.

### 글자 역할

위계는 세 단계다. 행에서는 제목만 밝고 굵게, ID·러너·시간은 흐리게, 숫자는 `numeric`(tabular-nums)으로 둔다. 역할마다 크기·굵기·줄 높이·자간이 한 묶음이다. `Text variant`로 쓰고, `Text`를 쓸 수 없는 요소(제목 태그를 직접 고르는 컴포넌트, 버튼 안 글자 등)에는 `stylex.props(textStyles(역할))`로 같은 스타일을 입힌다. 역할 목록은 `TEXT_VARIANTS`다.

| 단계          | 역할(`Text` 변형) | 크기 / 굵기 | 기본 요소 | 쓰는 곳                                                                                               |
| ------------- | ----------------- | ----------- | --------- | ----------------------------------------------------------------------------------------------------- |
| 1 화면을 대표 | `display`         | 26 / 600    | `h2`      | 큰 결론 문장. 지금 화면에서는 쓰지 않는다(0113에서 Dashboard·Stats 결론은 한 줄 머리 요약으로 옮겼다) |
|               | `page`            | 22 / 600    | `h1`      | 페이지 제목(화면 이름). 화면에 하나, `PageHeader` 한 줄 머리 안                                       |
|               | `heading`         | 20 / 600    | `h2`      | 주 구역 제목(Stats 구역). `Section titleRole="heading"`                                               |
|               | `panel`           | 17 / 600    | `h2`      | 상세 패널·다이얼로그 제목                                                                             |
| 2 읽는 내용   | `subheading`      | 15 / 600    | `h3`      | 보조 구역·카드 제목(Dashboard 칸반 칸·Runners 열, 둘 다 `h2`). `Section titleRole="subheading"`       |
|               | `title`           | 14 / 500    | `span`    | 행 제목(`RowTitle`과 같다)                                                                            |
|               | `body`            | 14 / 400    | `p`       | 설명 문단, 패널의 이유                                                                                |
| 3 흐린 보조   | `ui`              | 13 / 400    | `span`    | 일반 UI 글(본문 기본 크기)                                                                            |
|               | `meta`            | 13 / 400    | `span`    | ID, 러너, 시간처럼 흐린 값                                                                            |
|               | `label`           | 12 / 500    | `span`    | 열 머리글, 패널 블록 제목, 작은 라벨                                                                  |

예전 `section`(14 / 600) 변형은 `subheading`과 겹쳐 티켓 0074에서 뺐다. `Section`의 기본 제목, `GroupHeader` 제목, Run 상세 블록 제목은 `subheading`이다.

색만 바꿀 때는 `tone`을 준다: `strong`(밝은 글, 이름·값), `muted`(흐린 글), `disabled`(못 쓰는 항목), `problem`(빨강, 오류와 문제 뜻만). `textStyles(역할, tone)`도 같다. 결과 문장처럼 다시 읽은 뒤 포커스를 옮길 글은 `Text`에 `ref`, `role="status"`, `tabIndex={-1}`을 주면 포커스 링이 붙는다. 줄바꿈을 지킬 글은 `wrap="pre"`, 긴 값은 `wrap="anywhere"`다.

토큰: `fontSize`(`display 26`, `page 22`, `heading 20`, `panel 17`, `subheading 15`, `body 14`, `ui 13`, `small 12`, `label 11`, `input 16`), `fontWeight`(`regular`, `medium`, `semibold`), `lineHeight`(`tight`, `snug`, `normal`, `relaxed`), `letterSpacing`(`display`, `page`, `panel`, `label`), `fonts`(`sans`, `mono`). 굵기는 이 세 개만 쓴다. 토큰은 역할과 컴포넌트를 만들 때 `packages/ui` 안에서 쓴다.

### 면 역할

면은 역할로 고른다. 둥글기와 안쪽 여백이 역할에 묶여 있다. `Card surface={역할}`(기본 `card`)로 쓰고, `Card`가 맞지 않는 요소에는 `stylex.props(surfaceStyles(역할))`을 입힌다. 역할 목록은 `SURFACE_ROLES`다.

| 역할      | 면                  | 둥글기 / 안쪽 여백 | 쓰는 곳                                                                               | 쓰지 않는 곳                                 |
| --------- | ------------------- | ------------------ | ------------------------------------------------------------------------------------- | -------------------------------------------- |
| `card`    | `bgCard`            | 12 / 20            | 주 구역 카드. 한 덩어리로 보여야 하는 구역(Dashboard 칸반 칸, Run 상세 정보·타임라인) | 구역마다 습관처럼 두르지 않는다              |
| `plain`   | 없음                | 0 / 0              | 면 없는 구역. 제목과 목록만 둔다(Dashboard Runners 열, ADR 0010 10번)                 | 다른 면과 갈라 보여야 하는 덩어리            |
| `inset`   | `bgInset`           | 8 / 12             | 카드·패널 안의 안쪽 상자(터미널 끝부분, 명령 예시, 확인 결과 묶음)                    | 화면 바탕 바로 위. 그때는 `card`             |
| `problem` | `problemSoft`(빨강) | 12 / 16            | 문제 상자. 해결할 일을 알린다. 보통 `ProblemCallout`으로 쓴다                         | 문제가 아닌 강조. 빨강은 문제 뜻 하나다(5번) |

### 간격 `space`, 반경 `radius`, 그림자 `shadow`, 모션 `motion`, 크기 `size`

- `space`: `s1 4` `s2 8` `s3 12` `s4 16` `s5 20` `s6 24` `s8 32` `s10 40`. 아이콘과 글 사이처럼 좁은 틈에만 `px2 2`, `px6 6`.
  - 목록 화면 여백 `s8`, 구역 사이 `s10`, 패널 안 블록 사이 `s6`, 버튼 사이 `s2`.
- `radius`(ADR 0010 10번): `card 12`(카드, 다이얼로그), `control 8`(버튼, 행, 입력, 메뉴·팝업), `pill 6`(알약, 팝업 항목, 툴팁), `full`(점). `tokens.test.ts`가 값을 검사한다.
- `shadow.popover`: 떠 있는 면(메뉴, Select 목록, 툴팁, 다이얼로그, 토스트)에만. 구역에는 그림자를 쓰지 않는다.
- `motion`: 곡선은 `easeOut`(들어오기·나가기), `easeMove`(화면 안 이동), `easeSheet`(Sheet 열기). 시간은 `durationFast 150ms`(hover·팝업), `durationToast 180ms`, `durationSpin 900ms`(확인 목록의 진행 중 고리 한 바퀴), `durationSweep 1100ms`(화면을 여는 동안 본문 맨 위 진행 줄 한 번 지나감), `durationReducedFade 150ms`(움직임 줄이기와 한꺼번에 바뀔 때의 흐려지기), `durationItemEnter 220ms`·`durationItemExit 160ms`(목록 항목), `durationLineEnter 200ms`(타임라인 새 줄, 펼치는 묶음의 하위 줄), `durationLineFade 120ms`(접히는 묶음의 하위 줄), `durationArrival 1200ms`(도착 비추기), `durationPillColor 150ms`·`durationPillPop 180ms`(상태 알약), `durationRowMove 240ms`·`durationCardMove 300ms`(자리 바꾸기), `durationDialogOpen 180ms`·`durationDialogClose 140ms`, `durationSheetOpen 260ms`·`durationSheetClose 180ms`. 쓰는 규칙은 아래 「움직임」을 따른다.
- `size`의 Runs 보드 값(티켓 0173): `runsQueueWidth 360`(기다리는 런 카드), `runnerCardMinWidth 320`·`runnerCardMaxWidth 560`(러너 카드 최소·최대 폭, 티켓 0185), `runsMenuWidth 160`(끝난 런 메뉴). `breakpoints.runsBoardStacked`는 보드 폭 760px 밑에서 카드를 한 줄에 하나씩 쌓는다.

### 테마

지금은 다크만 있다. `colors`의 기본값이 다크 값이다. 라이트를 더할 때는 `tokens.stylex.ts`에 `stylex.createTheme(colors, { … })`로 **모든 키**를 채운 라이트 테마를 만들고, 루트에서 운영자 설정에 따라 테마 클래스를 붙인다. 컴포넌트는 토큰만 쓰므로 고칠 필요가 없다.

### 티켓 목록에서 바꾼 것

티켓 0003의 목록(Button, Badge, Table, Card, Tabs, Dialog, Menu/Select, Tooltip, Toast, Input)을 시안 B의 실제 쓰임에 맞췄다.

- **Badge → `StatusPill`**: 점 + 이름 알약 하나(ADR 0010 4번). 처음에는 `Status`·`Dot`(점 + 글)이었고 0049a에서 알약 하나로 합쳤다.
- **Card**: 처음에는 쓰지 않았고(ADR 0007), ADR 0010의 카드 화면(Dashboard To do, Runners)을 위해 0049a에서 `Card`·`Row`를 더했다.
- **더한 것**: 목록 + 상세 패널 분할(`SplitView`, `DetailPanel` 묶음), 정의 목록(`DefinitionList`), 글자 위계(`Text`), `PageHeader`, `Section`.
- **Menu/Select는 둘로 나눴다**: 행동·전환 메뉴는 `Menu`, 폼 값은 `Select`.

### 움직임(티켓 0152)

상태가 바뀐 곳을 눈으로 따라가게 할 때만 움직인다. 키보드·탭·필터·hover·로그 흐름·계속 도는 표시와 첫 화면 렌더는 움직이지 않는다.

| 쓰는 것                   | 언제                                                                                                                                                                                                                                           |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `MotionList`              | 항목이 생기고 빠지는 목록. `items`·`getKey`와 항목을 그리는 함수를 준다. 기본은 펼치며 들어오고 접히며 빠진다. 타임라인 새 줄은 `enter="rise"`. 빠짐이 끝나면 `onExited(key)`가 온다. 필터·탭을 바꿀 때는 `resetKey`를 바꿔 움직이지 않게 한다 |
| `MotionScope`             | 항목이 목록 사이를 옮겨 다니는 묶음(Dashboard 칸). 칸들을 함께 감싼다. 카드는 `move="card"`(300ms), 행은 기본 `row`(240ms)                                                                                                                     |
| `useMotionMove`           | 갱신을 직접 쥔 곳(사용자 행동)에서 `move(() => setState(...))`로 부른다. View Transitions API를 쓰고, 없으면 FLIP, 둘 다 안 되면 바로 바뀐다. props로만 바뀌는 목록은 부르지 않아도 FLIP으로 움직인다                                          |
| `StatusPill changeMotion` | 목록에서 상태가 바뀌는 알약. 색이 150ms에 바뀌고 한 번 1.06배로 커진다. 첫 렌더에는 움직이지 않는다. 화면을 연 뒤에 새로 생긴 알약은 `popOnMount`를 함께 준다                                                                                  |
| `Dialog`, `Sheet`         | 열기·닫기 움직임이 들어 있어 화면에서 할 일이 없다. 닫는 도중 다시 열면 그 자리에서 되돌아간다                                                                                                                                                 |

- 한꺼번에 `MOTION_BURST_LIMIT`(3)건보다 많이 바뀌면 미끄러지지 않고 흐려지며 바뀐다. 건수는 들어온 것·빠진 것·칸을 옮긴 것·순서가 실제로 바뀐 것만 센다. 밀려난 이웃은 세지 않는다.
- 옮겨 갈 자리가 보이는 영역 밖이거나 칸이 세로로 쌓여 있으면 그 항목은 흐려지며 바뀐다.
- `prefers-reduced-motion`에서는 이동·커지기를 빼고 150ms 이하 흐려지기만 남는다.
- `MotionList`의 부모에 `gap`을 주지 않는다. 접힌 행도 `gap`을 차지해 빠짐 끝에 튄다. 행 사이는 항목 안의 여백으로 둔다.
- 행 사이가 필요하면 `MotionList itemGap`(`card`·`row`)을 쓰고 부모는 `KanbanCards motionItems`·`TableRows motionItems`로 둔다. 여백이 항목과 함께 접히고 도착 비추기는 여백을 덮지 않는다. 항목 요소에 붙일 `data-*`는 `itemAttributes`로 준다. `TableRow`는 빠지는 동안 `disabled`를 줘 방향키가 건너뛰게 한다.
- 닫히는 `Sheet`는 포인터를 받지 않는다. 닫는 도중 뒤의 카드를 한 번 누르면 그 클릭이 카드에 닿아 Sheet가 바로 다시 열린다. Sheet가 열려 있거나 닫히는 동안 시작한 더블클릭의 둘째 클릭(`event.detail` 2 이상)은 닫힘이 끝난 뒤에 와도 무시한다. 둘째 클릭 때 Sheet가 열려 있으면 그대로 둔다.
- 기본 상태는 늘 보이는 상태다. 움직임이 돌지 않아도 내용이 숨지 않는다.
- 상위 이슈 펼치고 접기(티켓 0175)는 `useIssueGroupMotion(resetKey)`, `IssueGroupBody`, `IssueGroupLine`을 쓴다. 펼침 버튼을 누른 곳에서만 `toggle(id, opening, childCount)`을 부르고, 거르기·보기가 바뀌면 `resetKey`를 바꿔 움직임을 멈춘다. 높이는 `grid-template-rows` transition(열기 220ms, 닫기 160ms)이라 도중에 다시 누르면 그 자리에서 되돌아간다. 하위 줄은 30ms 간격으로 4px 내려오며 200ms에 나타나고(8줄까지, 하위 30개 초과면 줄 효과 없음), 닫을 때는 한꺼번에 120ms에 흐려진다. 움직이는 동안 마지막 하위 줄은 `surface="middle"`로 두고 카드 꼬리는 `IssueGroupBody`가 맡아 끝에서 높이가 튀지 않는다. `prefers-reduced-motion`이면 단계 없이 바로 바뀐다.

## 시간 표기

시간은 `apps/web/src/format/time.ts`의 `useTime()` 하나로 그린다(ADR 0010 7번). 진행 중인 것은 경과(`elapsed`, "<1 min"·"25 min"·"1 hr 3 min"·"2 days"), 지난 일은 상대 시간(`ago`, "Just now"·"25 min ago"·"3 hr ago"·하루 넘으면 날짜), 타임라인은 시각(`clock`, "10:45"), 기다린 시간·통계 같은 양은 `duration`(경과와 같은 표기)이다. 시각·날짜는 운영자 시간대(티켓 0044)로 그린다. "지금"은 서버가 데이터를 읽을 때 정해 경과 밀리초로 넘긴다.

## 새 컴포넌트를 더할 때

1. 동작은 `@ui-sdk/react`의 부품으로, 스타일은 StyleX와 토큰으로 `src/components/`에 만든다. UI SDK 상태별 스타일은 `className={(s) => cx(...)}`로 고른다(StyleX는 `data-*` 선택자를 쓰기 어렵다). 예외로 `className` 상태에 없는 열기·닫기 전환은 `":is([data-starting-style])"`·`":is([data-ending-style])"` 조건으로 쓴다(`Dialog`, `Sheet`).
2. 문구는 props로 받는다. 기본 문구를 컴포넌트에 넣지 않는다.
3. `src/index.ts`에서 export 하고, `components.test.tsx`에 서버 렌더 테스트를, `/ds`(`apps/web/src/ds/`)에 미리보기를, 이 문서에 언제 쓰는지를 더한다. `/ds` 미리보기가 빠지면 `apps/web/src/ds/page.test.tsx`가 실패한다.
4. UI SDK는 `0.1.0-beta`라 버전을 고정했다. 올릴 때는 `pnpm typecheck`(특히 `exactOptionalPropertyTypes`)와 `/ds`를 다시 확인한다.

### 브랜드 그림(티켓 0077)

기호·마스코트·색·워드마크·앱 아이콘을 쓰는 규칙은 브랜드 가이드 [`brand/README.md`](brand/README.md)에 모았다(티켓 0081).

원본 SVG는 `packages/ui/brand/`에 있다. 기호·한 색판·파비콘 전용판·워드마크(Manrope ExtraBold 아웃라인, `OFL-Manrope.txt`)·가로·세로 조합·마스코트 표정 넷·앱 아이콘 원본이다. 파비콘·앱 아이콘·트레이 그림은 `pnpm --filter @ganger/desktop brand-assets`로 이 원본에서 다시 만든다. 마스코트 몸·눈 같은 그림 전용 무채색은 `brand.*`에 두고 이 컴포넌트들만 쓴다. 노랑(취구·모자)은 강조색 `colors.accent`를 쓴다(티켓 0080).
